# Optional assessment adapter, version 1

This additive adapter keeps the published schema-1 `QualificationReport`, C ABI
and existing report consumers unchanged. Rust callers use
`nirs4all_preflight_core::assessment::extract_assessment`; a file consumer can run:

```sh
n4pf extract-assessment examples/assessment/report-v1.json \
  examples/assessment/context-v1.json > assessment.json
n4pf extract-findings examples/assessment/report-v1.json \
  examples/assessment/context-v1.json > findings.json
```

`examples/assessment/assessment-v1.json` is generated by this exact command. Its
input is explicitly synthetic; the repeated `a` digest is a placeholder, not a
claim about source provenance. A real consumer supplies its own canonical source
hash, dataset ID and engine/protocol provenance. The adapter never computes
scientific kernels and never requires Datasets or Domains as a dependency.

## Identity, availability and semantics

An assessment is identified by dataset/content hash, source, population, context,
producer, engine version and protocol version. Each metric retains its native
metric ID, protocol, view, scalar value, unit and reason. Its full identity is
`(metric_id, source_id, target_id, view_id, population_id, context_id, protocol_version)`.
Scalar extraction selects the exact declared source, target and population;
source-less global metrics remain in the original report without being assigned
to a source by inference. Consumers must not merge metrics from different views/populations or infer
equivalence to an older field from a similar display label.

The `report` property preserves the original JSON exactly, including unknown
extension fields, findings, capabilities, limitations, denominators and arrays.
Each selected scalar metric also preserves its original `native_metric` and
`native_status`. Status mapping is explicit:

| Native status | Scalar assessment availability | Value |
| --- | --- | --- |
| computed, numeric | available | Original number, including a real zero |
| not_applicable | not_applicable | null |
| insufficient_data / unsupported / not_identifiable / undefined / cancelled / error | unavailable | null; original reason retained |
| computed, missing or non-scalar | unavailable | null, `NON_SCALAR_OR_MISSING_NATIVE_VALUE`; full value survives in the raw metric/report |

`kind` separates `measured_observation`, `heuristic_signature` and `possible_cause`.
`signal_strength` and `evidence_coverage`, when explicitly provided, are distinct
nullable fractions in [0,1]. An absent value is unknown, never zero. A metric's
default `confidence_status` is `unknown`; signatures may be `unvalidated`.
The adapter refuses to manufacture validated physical-cause confidence. Legacy
finding `confidence` strings remain qualitative labels; they are not calibrated
probabilities. Findings preserve their separate `severity`, evidence references,
message and recommended `action`. A recommendation is an operational action,
not a measured observation or proof of its proposed physical cause.

`extract_findings` / `extract-findings` provides an independent optional
projection with `rule_id`, `context_id`, `kind`, `severity`, `confidence_status`,
nullable strength/coverage, structured metric identities in `evidence`, unresolved
evidence IDs, a separate `recommended_action`, and the lossless original finding.
Native/SNV views remain distinct even when they share a metric ID. Missing
references remain unresolved; a legacy `confidence: high` label does not become
validated confidence. Both projections leave the original schema-1 report intact.

The original report is local provenance and may contain identifying details.
Datasets' anonymized public projection must remove it and apply its own rules to
free text, identifiers, detailed findings and source hashes.

## Three consumer examples

1. **Standalone Preflight:** use the intrinsic example context. Scalar geometry
   is available; missing repeats remain `insufficient_data` in the original
   report and unavailable/null in the optional assessment. No model-performance
   or uncertainty-calibration claim is introduced.
2. **Datasets sidecar:** attach `assessment-v1.json` as an optional versioned
   assessment next to an existing card. Keep legacy card values unchanged until
   a mapping is explicitly qualified. Native `structure.effective_dimension`
   is not silently renamed to a historical PCA-Q ratio. Unknown/non-scalar
   fields remain available through the retained report.
3. **Domains task report:** the producer is `nirs4all-domains`, the scope is
   `task`, and `split_id`, `fit_population_id`, `evaluation_population_id` are
   mandatory and distinct for fit/evaluation. For example:

```json
{
  "dataset_id": "source-owner-dataset",
  "content_hash": "sha256:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "producer": "nirs4all-domains",
  "source_id": "nir",
  "population_id": "evaluation_real",
  "context_id": "train-test/split-v1",
  "scope": "task",
  "target_id": null,
  "split_id": "grouped-split-v1",
  "fit_population_id": "calibration_real",
  "evaluation_population_id": "evaluation_real",
  "semantics": {}
}
```

This context accompanies a real Domains report; it does not turn a Preflight
intrinsic report into a task assessment by relabelling it. Preflight refuses to
claim task-scoped production under its own producer identity. Intrinsic
assessments reject split/fit/evaluation fields, preventing test-dependent scores
from silently entering a pre-training intrinsic summary.

## Existing intrinsic protocols and migration limits

The optional 0.1.1 intrinsic protocols below are documented in
[intrinsic-protocols.md](intrinsic-protocols.md), with their native/WASM
conformance fixtures. Existing legacy card calculations remain separate unless
their exact protocol mapping has been qualified.

| Datasets concern | Existing shared owner / protocol | Migration rule |
| --- | --- | --- |
| PCA geometry, effective dimension | Preflight `structure.pca*`, `structure.effective_dimension`; Methods exact PCA and full covariance moments | Preserve native view, fit population, normalization, resolution and exact-moment availability. Effective dimension is not a Q/T² outlier ratio. |
| Repeatability | Methods `n4m_preflight_repeatability_compute`; Preflight repeatability protocols | Real declared repeat groups and masks required. Missing groups produce unavailable evidence. |
| Roughness/noise | Methods `n4m_preflight_noise_proxy_compute`; Preflight declared noise-proxy protocol | SG residuals, window, degree, masks and reference units remain explicit. It is not automatically equivalent to Datasets' old second-difference pseudo-SNR. |
| SNV sensitivity | Methods row SNV + Preflight `structure.snv_*` protocols | Preserve both native/SNV view identities; do not overwrite the original metric. |
| Neighbour geometry and clustering | Native Methods neighbours, HDBSCAN, ARI; Preflight protocols | Preserve representation, seed, distance and eligibility population. A neighbour-distance ratio is not LOF by naming. |
| RMS/SAM and affine report to the development mean spectrum | Methods `diagnostics.spectral_reference_qc`; Preflight `intrinsic.reference.*`, `spectral-reference-pairwise-valid.v1` | Optional `intrinsic_qc`; preserve the development-population mean reference, common-valid masks, units and eligible denominators. These metrics do not imply an instrument white reference or frozen train/test coverage. |
| Spikes, jumps and clipping | Methods `diagnostics.spectral_events_qc`; Preflight `intrinsic.events.*`, `spectral-events-declared-axis.v1` | Preserve the declared index/physical-axis mode, units, thresholds and eligible pairs/triples. `declared_clip_fraction` requires sensor bounds; absent bounds remain `not_applicable`. Observed-extrema occupancy is a separate descriptive proxy. |
| Train/test applicability and model-performance risk | Domains using a frozen training reference | Outside Preflight intrinsic protocols; no access to retained-test target values is added. |
| Physical cause | Heuristic interpretation layer | Separate observed signature, possible cause and recommended action. No absent-proof-to-zero coercion or uncalibrated probability. |

Migration tests cover legacy JSON with unknown extensions, unavailable evidence,
non-scalar values, source/population filtering, split context refusal, invalid
fractions and CLI export. Numerical conformance remains in the existing native
Methods/Preflight suites; this transport adapter performs no numerical port.
