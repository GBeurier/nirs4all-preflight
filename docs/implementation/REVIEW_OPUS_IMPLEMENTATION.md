12 October 2026. Reviewer: Claude Opus 5.5 (independent). ## Frontend findings and fixes

Severity reflects user-visible scientific or contract impact.

| # | Severity | Finding | Fix |
| --- | --- | --- | --- |
| F1 | **Critical** | `demo/src/synthetic.ts` set `repeat_type: "technical"` on `Sample`. Rust `Sample` denies unknown fields and declares repeats per X row in `SpectralSource.repetition_types` (`crates/nirs4all-preflight-core/src/lib.rs:41,64-82`). The pitfalls demo could never run. | `synthetic.ts:84` emits `source.repetition_types`: `rescan` for the three acquisitions of s01–s08, `unknown` elsewhere, and two `unknown` acquisitions for s09 to show the explicit "not averaged" exclusion. The doc comment lists every pitfall. Verified with CLI and WASM. |
| F2 | **Critical** | Unit `group` sent `options.independence_group_key`, which `Options` rejects (`core/lib.rs:133-146`). The engine reads `samples[].independence_group`. | Removed the field and the input box. The config shows how many samples declare `independence_group` (`input.ts`, `App.tsx:334`). |
| F3 | High | Source checkboxes and a single-target select subset the input before sending it. The default kept only the **first** target, silently dropping the others, and the report carries no trace that a subset was analysed. This fabricates a recomputation scope. | `buildEngineInput` (`input.ts:130`) now sends every source, sample and target, and edits options only. It also keeps `max_cells`/`max_samples` from the file, which were previously dropped. Source/target selection is now an explicitly labelled **display filter** over the engine's rows (`App.tsx:374`), with an "n / N rows shown" status. |
| F4 | High | Stale responses. Loading another dataset while an analysis was running let the old report land on the new dataset. "Validate" overwrote `sentInput`, so the Data tab and the downloaded input could describe a different input than the displayed report. | A job-generation counter ignores superseded responses (`App.tsx:63,114-126`). Loading new data cancels the running job. A report is stored together with the exact input and origin that produced it (`Result` type). The new host test checks that a terminated worker's message cannot resolve the next job. |
| F5 | High | Severity vocabulary: UI accepted `info/warning/critical`, but the spec (§6) defines `info/warning/high/blocking`. A `blocking` or `high` engine finding was **downgraded to "warning"**. | `types.ts:31`, `report.ts`, `locale.ts`, CSS: the four spec severities are recognised and tested. |
| F6 | Medium | `formatQualificationValue` used `toPrecision(6)` on all numbers, so counts of 1,000,000 or more were shown rounded (1234567 → 1234570). | Integers are shown exactly (`report.ts:97`) and covered by a test. |
| F7 | Medium | Metrics sharing one id in different contexts (`measurement.repeatability_sd` × campaign) rendered as indistinguishable rows. | `EvidenceTable` shows scalar parameters (`repeat_type=rescan · instrument=… · campaign=…`), leaving arrays to the JSON (`report.ts:114`, `EvidenceTable.tsx:47`). |
| F8 | Medium | The spectra preview drew rows of **every** partition, retained test included, under a plain "source" title (spec §4: the retained test is not inspected outside an audit profile). The incomplete-row count mixed all partitions. | `DataPreview` (`App.tsx:463`) draws only complete real-development rows (≤12, file order). Its caption and table count retained-test, prediction, augmented, undeclared-sample and incomplete rows as **not drawn**. The axis range is read from the first and last values, with no min/max computation. |
| F9 | Medium | PCA scores published by the engine were not shown. | New Structure tab (`App.tsx:414`) uses `viz/PcaScatter` plus `ChartDataTable`. Points come directly from `structure.pca_scores`. Unavailable statuses are shown with their reason. The retained fraction comes from `structure.explained_variance_retained`. No per-axis variance percentages are given: computing them would be frontend arithmetic. The caption notes that PC1 and PC2 are scaled independently. The table is capped at 500 rows and points to the full JSON. The id column is labelled "physical\|instrument\|campaign" (see B3). |
| F10 | Medium | Demo exports were not marked as demonstration (spec §9). | Results show a "Demonstration — synthetic data" banner. Downloads are named `nirs4all-preflight-synthetic-demo-*`. The page states that the engine report itself still lacks the label (B4). |
| F11 | Low | `downloadText` clicked a detached anchor and revoked the object URL synchronously, which some browsers ignore or abort. | It attaches the anchor and revokes the URL on the next tick (`download.ts:7-10`). Chromium downloads were verified. |
| F12 | Low | Seed: arbitrary numbers were truncated or clamped silently, and seeds above 2^53 could not reach the u64 field exactly. | `parseSeed` accepts only safe non-negative integers. Invalid input keeps the previous value and shows an `aria-invalid` hint. |
| F13 | Low | Upload validation checked only the top-level arrays, so a malformed source crashed the summary render. | `parseCanonicalInput` checks the fields the page dereferences. `targets`/`options` default like serde. Anything else is still left to the engine. |
| F14 | Low (a11y) | Inactive tabs had `aria-controls` pointing at absent panels. A step change left focus on a removed button. The topbar overflowed at 320 px. | `aria-controls` is set only on the active tab. Focus moves to `main` on step change. The topbar wraps under 760 px. All verified in Chromium. |

Not changed: `runtime.ts`, `package.json`, dependencies, the vendored UI tarball, and the other session's dirty `workbench/`/`playground/` files. `demo/dist` (gitignored) was last built against the fresh UI build. `demo/node_modules/nirs4all-ui` was restored to the tarball contents.

## Backend findings for root (not edited)

| # | Severity | Path | Finding |
| --- | --- | --- | --- |
| B1 | **High (scientific)** | `crates/nirs4all-preflight/src/lib.rs:208-230` | The exact-duplicate integrity pass only hashes **development** rows. An identical spectrum in development and retained test under different physical IDs is undetected (reproduced: 0 pairs, no finding, `valid: true`). This is the most direct undocumented-leakage signal. Spec §3 says disjoint row hashes complement identity checks. Hashing X_test is an integrity check, not learning on it. Suggest a separate `integrity.cross_partition_exact_duplicate_pairs` metric with its own finding. |
| B2 | Medium | `lib.rs:1204-1244` | Engine HTML export: statuses use Rust `Debug` (`Computed`, `NotIdentifiable`) rather than wire names. It lacks engine/protocol/schema versions, units, denominators and context parameters, so the two repeat contexts look identical. Tables have no `<caption>`/`scope`. Findings omit severity and confidence. `lang="en"` is fixed. Spec §9 requires exact versions and accessible tables in exports. Large inline arrays (`pca_scores`, up to 100k cells) are dumped into one cell. |
| B3 | Medium | `lib.rs:330,435` | `structure.pca_scores.sample_ids` holds `physical\|instrument\|campaign` aggregation keys, not `samples[].sample_id`. Any host joining on that name is wrong. Rename it (e.g. `unit_ids`) or add `representative_sample_ids`. The UI labels it correctly for now. |
| B4 | Medium | `core/lib.rs:12-22,637-649` | The input/report cannot carry a demonstration/dataset label. `deny_unknown_fields` forbids adding one, so demo exports can be labelled only by file name (spec §9 asks for the label in every export). |
| B5 | Low | `lib.rs:964-967` | Several metrics share `metric_id` + `source_id` + `target_id`. They are distinguished only by `parameters`. A stable context key or `scope` value would make them addressable. |
| B6 | Low | `lib.rs:1086` | `n_excluded_retained_or_augmented` also counts `prediction` partition values. The name understates its content. |
| B7 | Low | `bindings/wasm/src/lib.rs:22-26` | JS callback exceptions become free-text `reason_code`s (`METHODS_CALLBACK_FAILED: JsValue(RangeError…)`), which are not stable codes. |
| B8 | Low (packaging) | `bindings/wasm/package.json:30` | `@nirs4all/methods` points at `file:../../../../../../tmp/…tgz`. This is unpublishable, and spec §11 forbids local sibling paths. |
| B9 | Low | `crates/nirs4all-preflight-capi/src/lib.rs:21` | `n4pf_version()` is hard-coded rather than `ENGINE_VERSION`, so it can drift. |

Memory/ABI contract pass: the C ABI `run` contains panics with `catch_unwind`, frees only its own boxed slice, and clears descriptors idempotently. `NativeMethodsProvider` buffer sizes match `metrics.h` (scores n×k, loadings k×p, 2 moments, 8 summary values, 4 contrast values, i32 band status, i64 counts and indices). Shape and budget checks are in place before every FFI call. The Methods JS wrapper frees every `_malloc` and view in `finally` and reads heap views after all allocations. No out-of-bounds or ownership defect was found. The Methods kernels are analytically consistent: trace(C²) through the smaller Gram matrix, balanced one-way ICC(1,1) with negative values kept, type-7 quartiles, group-excluding k-NN, and the two documented contrast definitions.

## Remaining limits

- Root must repack `demo/vendor/nirs4all-ui.tgz` (or pin a published `nirs4all-ui`) so the demo picks up F5–F7. The demo compiles against both versions.
- The browser evidence covers headless Chromium on one machine. No Firefox, WebKit, screen reader, axe, 400 % zoom or performance/memory budget measurements were done. Cancellation was exercised only during worker start-up, because the synthetic analysis finishes too fast to cancel mid-protocol.
- The engine provides no progress or partial snapshots, so a cancelled run shows no partial report (spec §9 snapshots are not implemented).
- `PcaScatter` has no aspect lock. The caption warns about this; the shared component was not changed.
- Seeds above 2^53 in uploaded JSON are already rounded by `JSON.parse`. A BigInt-aware parser would be needed if the engine starts using seeds.
