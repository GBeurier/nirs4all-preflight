# Engine reuse and current alpha boundary

The preflight Rust engine owns input validation, population selection, source and context separation, protocol orchestration, report status, and finding rules. It does not reimplement generic numerical methods.

The explicit `UnavailableMethodsProvider` lets callers validate and inspect population/target coverage without implying that unavailable numerical diagnostics were computed. Every unavailable metric has a status, reason, and null value. The report is marked `exploratory`; alpha thresholds have not been qualified. The CLI uses this provider unless a Methods library is selected by `--methods-library` or `N4M_LIBRARY_PATH`.

For structure, observations from the same physical object are averaged only inside one source, instrument and campaign when every repeated acquisition has a declared technical repetition type. Physical objects occurring in multiple contexts, or under multiple sample IDs, are excluded from this single-context PCA profile with counts reported. Unknown or biological repeat types remain excluded from PCA aggregation with counts reported; single observations remain eligible. Rows with masked bands are excluded from complete-case PCA and counted. Retained-test and augmented samples are excluded. Technical repeatability is computed separately for each repetition type, instrument and campaign. No silent imputation, interpolation, source concatenation or reference reconciliation occurs.

Identity linkage is validated before any Methods call on whole linked components of the original rows: physical samples, individuals, augmentation parents, declared `independence_group` (always, whatever the analysis unit) and reference groups. Prediction rows take no partition role but remain identity bridges, so a development row linked to a retained-test row through a prediction row is refused (`IDENTITY_LEAKAGE`, or `REFERENCE_LEAKAGE` when only reference groups close the component). Retained-test target content is never decoded: input JSON is parsed with partitions and identifiers first, target `value` and `category` are held as unparsed JSON text (`serde_json` `RawValue`, which the tokenizer only skips), and a retained-test reference keeps its identity fields while its value and category are dropped unread, whatever their JSON text (including tokens such as `1e400` that a typed parser rejects); development values keep their typed check. Identity components use structured keys (`IdentityKey`: sample, physical, individual, group, and (target, reference group)), so identifiers containing separators never collide; the local-contrast neighbor groups use the same keys. The WASM runtime also exposes `analyzeJson`/`validateJson`, which hand the JSON text to Rust unchanged. Fold plans returned by the validation provider are checked against these components before any score is reported (see the probe paragraph below).


Typed metadata. The input carries an optional `metadata` table (schema version 1, optional fields only): `columns` declare a `name`, a `kind` (`categorical` or `continuous`) and, for continuous columns, a `unit`; `values` map `sample_id` → column → value, where a JSON string is a categorical level, a JSON number a continuous value, and absent or `null` means missing. Metadata are sample-level because `instrument` and `campaign` already are and because association units are built from samples; an acquisition-level covariate (for example a per-scan temperature) can be declared only when it is constant for the sample. Validation is blocking for an empty, duplicated or reserved name (`instrument`, `campaign`), a unit on a categorical column or an empty unit (`INVALID_METADATA_COLUMN`), an undeclared sample (`UNKNOWN_SAMPLE`), an undeclared column (`UNKNOWN_METADATA_COLUMN`), a string for a continuous column or a number for a categorical one (`METADATA_TYPE_MISMATCH`, nothing is converted) and an empty level or non-finite value (`INVALID_METADATA_VALUE`). It warns, without blocking, for a continuous column without unit (`UNKNOWN_METADATA_UNIT`) and for a column whose values differ inside a linked identity component (`METADATA_VARIES_WITHIN_INDEPENDENCE_UNIT`). `QualificationInput::metadata_factors()` returns the analysable factors in report order (`instrument`, `campaign`, then declared columns) with name, kind, unit and origin (`sample_field` or `declared`); `QualificationInput::metadata_value(&factor, &sample)` returns `MetadataLevel::Category(&str)` or `MetadataLevel::Value(f64)`, or `None` when missing. Other protocols (confounding) read metadata only through these two functions.

Metadata–target associations (`metadata_association.v1`) test every factor against every target. The population is the exact, internally consistent references of real development samples; retained-test, prediction and augmented references are counted and their Y is never read, not even by input validation (which checks the partition before any Y content). Independence units are the identity components of all samples, built by `independence_components` from every identity and reference link before any analytic exclusion: physical sample, individual, augmentation parent, `independence_group` when the unit is `group`, and the `reference_group_id` of every reference of the target, whatever its partition, status or position in the input. Eligible references are then grouped by component, ordered by their smallest sample ID, and receive one vote each. Units with missing metadata are excluded and counted. Units whose target or metadata varies internally are excluded from the descriptive effect and make the test `not_identifiable`; when these exclusions leave fewer than two levels or three units, the structural reason is reported instead of `SINGLE_METADATA_LEVEL`. The statistic follows the types: categorical metadata use eta² and ANOVA F (continuous target) or Cramér V and Pearson χ² (categorical target), with per-level Y summaries or class counts; continuous metadata use eta² and F of the metadata across target classes (categorical target, per-class metadata summaries; the kernel permutes metadata values across units, which is equivalent in law to permuting target labels), or Spearman's rho on average ranks with Pearson's r as a descriptive companion (continuous target; two-sided test on |rho|). Spearman is the tested statistic because it is invariant to monotone transformations of covariates such as temperature and robust to isolated extreme values. A continuous column with one value is `not_applicable` (`CONSTANT_METADATA_VALUE`).

`association.metadata_target_test` carries a versioned `PermutationPlan` (`permutation_plan.v1`): null hypothesis, tested effect, statistic (`eta_squared`, `cramers_v_squared`, `eta_squared_of_metadata_by_target_class` or `abs_spearman_rho_two_sided`), exchangeable unit and whether exchangeability was declared, restrictions (`none_single_block`), block sizes, reduced model (none), draw method, Methods PCG64 RNG, decimal-string seed and its derivation, the log10 combinatorial bound on distinct arrangements, requested/executed counts, the Monte Carlo step `1/(B+1)`, the exact enumeration (`n_enumerated_arrangements`, `exact_minimum_p_value`) when the space has at most 100,000 distinct arrangements, the resulting `resolution` and its `resolution_basis` (`exact_enumeration`, or `lower_bound_from_combinatorial_bound` when the space is larger and `1/bound` is only a lower bound on the smallest exact p-value), p-value convention `(1+b)/(1+B)` and tie tolerance. The only executable plan is uniform unit-label permutation over one block. It requires a declared independence unit and `options.exchangeable_units = true`. In order, an unknown unit, a missing group, target or metadata varying inside a unit, a saturated design (one unit per level or per target class, `SATURATED_DESIGN`: the statistic cannot change under permutation), a target constant in the block and undeclared exchangeability return `not_identifiable` with their reason code. No restricted, crossed or residual permutation is substituted.

The family is every identifiable metadata × target test of the report (`association.metadata_target_family`), with Holm at 5 %. A test is executed only if its resolution is at most `0.05/m`; otherwise it is `insufficient_data` (`PERMUTATION_RESOLUTION_INSUFFICIENT`), carries no p-value, and enters Holm as p = 1. B = 999. Each test seed is `splitmix64_finalizer(options.seed XOR fnv1a64(domain))`, where the domain names provider, protocol, target and metadata. The root `options.seed` accepts a JSON number or a canonical decimal string (the WASM wrapper converts bigint and safe-integer inputs and refuses unsafe numbers), and all seeds are serialized as decimal strings so JavaScript hosts never round them. Executed permutations are recorded even when the Holm correction is unavailable; the test value then has `p_value_holm = null`, `rejects_null_at_family_alpha = null` and `multiplicity_available = false` with its reason, and no finding. Benjamini–Hochberg adjusted values of the same family are published as `p_value_bh_exploratory`, an exploratory secondary view (`exploratory_secondary` in the family metric, dependence assumption independence or PRDS, declared and not verified); they are never used for findings. A Holm rejection produces the exploratory finding `association.metadata_target.v1` with confidence `unknown`; it is not causal evidence.

The alpha integrity pass counts exact spectral pairs spanning declared physical samples after normalizing negative zero and honoring masks. It separately counts exact pairs across real development and retained-test observations under different physical IDs, with affected-observation denominators. This integrity check reads retained-test X only; it does not fit on test rows or inspect retained-test Y. Findings remain suspicions with unknown confidence. Exact matches never rewrite sample identity automatically.

Quasi-duplicates run only when `options.quasi_duplicates.tolerance` is declared (finite, positive, in the units of the chosen view); no default tolerance exists. Without it, `integrity.quasi_duplicate_pairs` and `integrity.cross_partition_quasi_duplicate_pairs` are `not_applicable` with `QUASI_DUPLICATE_TOLERANCE_NOT_DECLARED`, and the report's `quasi_duplicates` capability is unavailable with the same reason. The distance is the root-mean-square band difference in the declared view (`native` or SNV, reported as view `canonical:snv`) and context (`instrument_campaign`, the default, or `source`). Populations follow the exact pass: complete-case real development rows, pairs inside one physical sample excluded, and a separate development × retained-test comparison that reads retained-test X only. Each metric reports tolerance and unit, candidate and suspect pair counts, suspect-pair rate, affected-observation fractions and up to 1,000 listed pairs. Exact duplicates are included. Findings `identity.possible_quasi_duplicate_repeats.v1` (warning) and `identity.possible_cross_partition_quasi_duplicate.v1` (high) carry unknown confidence and never rewrite identities.

`measurement.noise_proxy` (per band) and `measurement.noise_proxy_pooled` are computed per instrument × campaign on native real development acquisitions with equal weight. They are the root mean square of the Savitzky–Golay smoothing residual (default 11 bands, polyorder 2, configurable in `options.noise_proxy`) divided by the filter's white-noise residual gain. Only interior bands are evaluated; there is no padding at the edges. A window containing a masked cell is skipped. The axis must be uniform within 10⁻³ of its mean spacing (`NON_UNIFORM_AXIS` otherwise). Window, physical width, normalization, edge and mask behavior and the assumption (locally polynomial signal, white noise) are declared parameters. The label is `noise_proxy_not_snr`; no SNR is produced.

`structure.snv_sensitivity` is on by default (`options.snv_sensitivity: false` disables it). SNV is applied to each acquisition of the canonical PCA population. The result is then aggregated with the same sample means and decomposed with the same number of components, as view `canonical:snv_centered`. The metric reports, for both views, eigenvalue shares of the full variance trace, the first-component and retained shares, the full-moment effective dimension, and the differences between the two views. `structure.snv_pca_eigenvalues` and `structure.snv_effective_dimension` give the SNV view itself. The comparison is descriptive and makes no attribution to nuisance or chemistry.

The JSON input and report schemas are version 1. Internal Methods adapter contracts are Rust structs in `nirs4all-preflight-core/src/lib.rs`; host adapters must validate native shapes, finite numbers, and ABI versions before returning values. C API, WASM and language bindings must call this same engine, never duplicate the protocol.

PCA reports scores with actual representative declared sample IDs and separate aggregation keys inline up to 100,000 score cells, full variance moments, and retained explained-variance fraction. The inline limit is an explicit alpha report budget; a future asset transport is needed for larger score tables. A zero-rank source has undefined PCA geometry and local contrast. Input and report carry an optional `data_origin` label, including `synthetic` for demonstrations. The HTML export prints audit context and summarizes large arrays; JSON remains the complete scientific record.

Clustering (PF-05, exploratory, unqualified) uses the same eligible aggregated samples and canonical PCA scores as `structure.*`, in their canonical BTreeMap order. HDBSCAN results depend on row order and tie order, so that order is part of the protocol. The policy is frozen as follows:

- Parameters: `min_cluster_size = min_samples = max(5, ceil(n/20))`, where `min_samples` includes the sample itself, with EOM selection and `allow_single_cluster = false`. Fewer than `2 × min_cluster_size` eligible samples gives `FEWER_THAN_TWO_MIN_CLUSTER_SIZES`.
- Subsampling: 50 seeded subsamples without replacement of `ceil(0.8 × U)` independent units. A unit is the eligible physical sample, or the declared `independence_group` when `independence_unit = group`; a missing group gives `MISSING_INDEPENDENCE_GROUP`. The RNG is SplitMix64 seeded with `seed xor fnv1a64(source_id)`, followed by a partial Fisher–Yates shuffle.
- Refit: each subsample repeats centering, PCA (`min(10, m-2, p)` components) and HDBSCAN on the aggregated spectra. It does this twice: with `ceil(0.8 × parameter)` (floors 2 and 1), and with the constant full-sample parameters as a sensitivity variant.
- Comparison: on common sample identities against the full partition. ARI is computed only on samples assigned in both partitions, when at least 10 such samples exist and both partitions have two clusters there. Methods summarizes the distributions of ARI, assigned/noise agreement, cluster count, noise fraction, intersection size and compared fraction.
- Budget: work above `50 × n² × (p + 20) = 2.5e10` gives `STABILITY_WORK_BUDGET_EXCEEDED`.

Two protocol parts are not delivered yet and are reported as unavailable: cluster appearance frequency (`CLUSTER_MATCHING_NOT_QUALIFIED`) and the Gaussian null model (`NULL_MODEL_NOT_IMPLEMENTED`). Findings are `structure.clustering.uncertain_partition.v1` or `structure.clustering.continuous_structure.v1`, both with confidence `unknown`. They never state a firm number of clusters, and membership is labelled as a relative strength, not a probability. On a 60-sample three-blob input, native and WASM gave identical labels, counts and denominators, with numeric values within 1.3e-15 relative. Because HDBSCAN breaks exact ties, last-ulp PCA differences between hosts could still flip a near-tie on other data, so cross-host partition parity is not claimed beyond such checks.

Confounding (`confounding.v1`, PF-06 first half, exploratory, unqualified) uses the same eligible aggregated samples and canonical PCA scores as `structure.*` and clustering. Its rows are independence units: the identity components of `independence_components` (every declared sample; physical sample, individual, augmentation parent, `independence_group` for unit `group`, and the reference groups of every target), built before any exclusion and then projected onto the eligible rows, so samples absent from the source, masked out of the structure or augmented still link the rows they connect. A unit's coordinate is the equal-weight running mean of its rows' scores (no sum that could overflow); with unit `sample` and no links the coordinates are the scores themselves. Distances are Euclidean. Factors are the categorical metadata of `QualificationInput::metadata_factors()` (`instrument`, `campaign`, then categorical columns of the typed metadata map), read with `metadata_value()`. One population is shared by every factor so that sums of squares are comparable: units with a missing factor are excluded and counted, and units whose factor varies internally are excluded, counted and make every test of the source `not_identifiable` (`METADATA_VARIES_WITHIN_INDEPENDENCE_UNIT`). With unit `reference_group`, a participating unit whose component carries no reference group makes every test `not_identifiable` (`REFERENCE_GROUP_UNRESOLVED`, denominator `n_units_without_reference_group`); no sample-level plan is substituted. Fewer than three units gives `FEWER_THAN_THREE_INDEPENDENCE_UNITS`; no declared factor gives `NO_DECLARED_FACTOR`; a single-level factor gives `SINGLE_FACTOR_LEVEL`.

- `confounding.design` lists factor levels with unit counts, pairwise crossing tables, and per factor the nominal df, the identifiable df given the cells of the other varying factors (levels minus the connected components of the level × other-cell occupancy graph, from Methods), the design rank with those cells, `aliased_with_other_factor_cells` (identifiable df 0 relative to the cells of the other factors, interactions included), `identifiable_under_additive_model` (Freedman–Lane df > 0 given the other main effects), `partially_confounded` and `determined_by` (other factors each of whose levels holds a single level of this factor). A factor can be aliased with the cells yet identifiable additively (A = B xor C): the finding is then `confounding.aliased_with_other_cells.v1` (info, separation only if interactions are absent); `confounding.aliased_factors.v1` (warning) is reserved for factors that neither design can separate.
- `confounding.variance_partition` reports the total SS, per factor the marginal R² (factor alone), the unique R² given the other factors' cells (`SS(cells + factor) − SS(cells)`, the vegan `adonis2(by = "margin")` SS when there is one other factor), partial R², pseudo-F and df, and the R² of all factor-level combinations. `shares_are_not_additive` is always true; no share is presented as exclusive.
- `confounding.dispersion` is PERMDISP per factor (vegan `betadisper(type = "centroid")`): mean distance to each level centroid and the ANOVA F. It is a diagnostic only and never validates exchangeability or a PERMANOVA.
- Tests carry a `permutation_plan.v1`: `confounding.permanova_marginal_test` (free permutation of units, `none_single_block`), `confounding.permanova_conditional_test` (units permuted only inside the cells of the other varying factors, `within_blocks`, block sizes listed; blocks never move) and `confounding.permdisp_test` (permutation of the ANOVA residuals of the distances, as vegan `permutest`). The statistic is the pseudo-F (PERMANOVA, `permanova_pseudo_f` or `permanova_pseudo_f_given_strata`) or the ANOVA F of the distances (PERMDISP, `permdisp_anova_f`); as vegan, a draw counts when `F_perm >= F_obs − sqrt(DBL_EPSILON)` (`tie_tolerance`), never on a monotone transform of F. A conditional test with identifiable df 0 is `not_identifiable` (`FACTOR_ALIASED_WITH_OTHER_FACTORS`); with no other varying factor it is `not_applicable` (`NO_OTHER_VARYING_FACTOR`). An undefined statistic is `undefined` (`PSEUDO_F_UNDEFINED`, `DISPERSION_F_UNDEFINED`; a zero total SS makes the partition `ZERO_TOTAL_VARIANCE`). As for associations, an unknown unit, a missing group or undeclared `exchangeable_units` makes every test `not_identifiable`. The conditional test tests "no effect of the factor in any cell of the other factors" (maintainer decision; the Freedman–Lane test below complements it); strata where the factor is constant contribute no admissible permutation. Tests concern fixed effects of the observed levels and say nothing about new instruments or campaigns.
- `confounding.permanova_freedman_lane_test` is a second, separate conditional test of each factor: the main effect given the additive main effects of the other varying factors (intercept + other main effects, no interaction, `reduced_model` filled in the plan), by Freedman–Lane permutation of the reduced-model residuals over all units (`none_single_block`, statistic `permanova_pseudo_f_given_main_effects`, Methods `n4m_stats_permanova_freedman_lane`). It is approximate (exchangeable residuals) but its null admits interactions with the other factors, whereas the within-cells test is exact under the stricter null "no effect in any cell". A separate metric, not a mode of `confounding.permanova_conditional_test`, keeps one null hypothesis and one plan per metric and lets both enter the Holm family as distinct hypotheses. A saturated reduced model gives `not_identifiable` `REDUCED_MODEL_SATURATED`, an aliased factor `FACTOR_ALIASED_WITH_OTHER_FACTORS`, and a design without residual df `SATURATED_DESIGN` (also applied to the marginal and within-cells tests). The variance partition adds `*_given_other_main_effects` values and the design `df_identifiable_given_other_main_effects`. A Holm rejection gives the finding `confounding.main_effect_structure.v1`.
- Families: `confounding.permanova_family` (marginal, within-cells and Freedman–Lane tests of one source) and `confounding.permdisp_family`, each with Holm at 5 %, a resolution guard `max(1/(B+1), 10^−log10 distinct) <= 0.05/m` (`resolution_basis = lower_bound_from_combinatorial_bound`: no exact enumeration exists for these statistics, so the bound only bounds the smallest attainable p from below), otherwise `PERMUTATION_RESOLUTION_INSUFFICIENT` and p = 1 in Holm, and B = 999. Seeds are `derive_seed(options.seed, "nirs4all-preflight\0methods\0confounding.v1\0{source}\0{test}\0{factor}")`, the derivation shared with associations (`nirs4all_preflight_core::derive_seed`), sent as decimal strings.
- Findings, all with confidence `unknown`: `confounding.aliased_factors.v1` (warning, separate effects not identifiable; complete the crossings and check Y coverage of each crossing and the metadata–Y associations), `confounding.marginal_structure.v1` and `confounding.conditional_structure.v1` (warning, Holm rejection; compare with the metadata–Y association and hold out the factor's levels if the intended use includes new levels; never causal) and `confounding.dispersion_heterogeneity.v1` (info). When metadata associations are reported, their metric is cited as evidence.

On `examples/confounding.json` (instrument × campaign, 2026 holding instrument b only), an independent NumPy 2.2.6 reproduction on the reported scores (`lstsq` on full one-hot designs, `default_rng` draws) matched every R² within 1e-15 and every permutation count, natively and in WASM. Not delivered: residual (Freedman–Lane) permutation under a reduced model, nested or random domain factors, cluster explanations and prediction of metadata from X; domain shift remains `PROTOCOL_NOT_IMPLEMENTED`.

Provider failures are structured (`ProviderError { kind, reason }`) and shared by every capability. `unsupported` is reserved for an absent capability or a declared limit (library or ABI missing, work and memory budgets, Methods `UNSUPPORTED`/`NOT_IMPLEMENTED`/ABI/version/backend statuses) and gives the metric status `unsupported`; numerical failures (Methods `NUMERICAL_FAILURE`, `CONVERGENCE_FAILED`) and internal failures (invalid requests, memory, callback transport) give `error`. The reason is a stable code, `METHODS_<STATUS>` for Methods statuses: the native adapter maps the C status, and the WASM adapter forwards the Methods exception status for the Rust engine to map with the same function, so CPU and WASM report the same kind and reason.

Every confounding metric carries a `numerical_domain` parameter. The Methods kernels centre each column before choosing a power-of-two scale from the centred variation (constant columns and offsets have no effect), compute every residual sum of squares from explicit residuals (observation and each permutation), form F in the scaled unit and return `METHODS_NUMERICAL_FAILURE` (status `error`) when a sum of squares or a distance is not representable as a double. Engine tests check scale invariance of R², pseudo-F and permutation counts for spectra scaled by 2^k, k in {−500, −100, 100, 500, 1000}, or an explicit error. At k = −1000 the canonical PCA (`n4m_preflight_pca_compute`, outside this protocol) returns zero eigenvalues, so the structure is reported `ZERO_NUMERICAL_RANK`; a 1e300 constant band makes that PCA return `METHODS_NUMERICAL_FAILURE`. Both are upstream PCA limits, reported rather than masked here.

Validation probe (`validation_probe.v1`, PF-04, exploratory, unqualified). It runs once per source × continuous target × fixed recipe:

- `pls`: Methods `models.pls.pls_regression`, NIPALS.
- `pcr`: Methods `models.pls.pcr`.

Both recipes center X and Y inside each fit and do not scale. `options.validation_probe` sets `enabled` (default true), `estimators` (default both) and `max_fits` (default 500).

- Population. The probe uses real development samples with exact, internally consistent references; retained-test, prediction and augmented rows are never read. Technical repeats within one physical sample × instrument × campaign are averaged by Methods `n4m_stats_group_means` before any fit, giving one OOF prediction per sample. Multi-context physical samples, ambiguous or non-technical repeats, unreferenced samples and incomplete rows are excluded and counted. Domains are structured `(instrument, campaign)` pairs; an absent value stays `null` and never merges with another domain.
- Components. They come from the shared `independence_components` (`IdentityKey`), built over every sample before any exclusion. They link physical sample, individual, augmentation parent, reference group of the target and, for `independence_unit = group`, the declared group. A component never crosses a fold. Cross-partition links are refused earlier by input validation, so no FIT runs.
- Refusals before any fit:
  - `INDEPENDENCE_UNIT_UNKNOWN`, `MISSING_INDEPENDENCE_GROUP`;
  - `EXACT_DUPLICATE_SPECTRUM_ACROSS_COMPONENTS`, `CONSTANT_TARGET`;
  - `FEWER_THAN_THREE_INDEPENDENT_GROUPS`, `TOO_FEW_SAMPLES_FOR_COMPONENT_GRID`, `ZERO_NUMERICAL_RANK`;
  - `FIT_BUDGET_EXCEEDED`, `NUMERICAL_DOMAIN_EXCEEDED`;
  - `PROBE_METHODS_KERNELS_NOT_CONFIGURED`.

  Categorical targets give `CLASSIFICATION_PROBE_NOT_QUALIFIED`; no Methods classifier is qualified on every host.
- Plan. With G components, the probe uses `min(5, G)` outer folds and `min(3, outer − 1)` inner folds. Grouped K-fold assigns the largest group to the lightest fold, so every fold holds at least one group and at most `n/k + s_max` rows. The smallest inner training pool is therefore at least `B = (n(1 − 1/outer) − s_max)(1 − 1/inner) − s_max`. The grid is `1..=min(10, p, r, ⌊B⌋ − 1)`, where `r` is the numerical rank of the centered aggregated matrix: Methods PCA eigenvalues with the NumPy `matrix_rank` rule `s_i > s_1 max(n, p) ε`. PLS and PCR beyond the rank are ill-posed. The plan expects exactly `outer × (grid × inner + 1)` fits.
- DAG-ML. `execute_nested_selection` owns every loop: it builds all fold sets before any fit, runs FIT_CV of each candidate on the inner folds, selects by minimum pooled inner-OOF RMSE (`select_candidate`, ties to fewer components), then runs FIT_CV of the winner on each outer training pool, which predicts only its validation rows. Masked references are refused there. Errors keep their taxonomy code (`DAG_ML_<CODE>`, status `error`) and carry the outer fold and candidate in `provider_error_detail`.
- Re-verification. Preflight checks everything the provider returns before publishing it, without a new CV:
  - partitions, unsplit components and unique fold IDs;
  - inner folds inside each outer training pool;
  - the exact grid, and the selection as the minimum inner RMSE with the tie rule;
  - the exact fit count;
  - one OOF row per sample with its exact target bits;
  - finite, in-range provider scores.

  Fold-train means then come from Methods `summary`. Model and baseline RMSE, MAE and R² come from `n4m_stats_regression_scores` on the OOF rows. The provider's scores must agree within a relative 1e-9 (`PROVIDER_SCORES_DISAGREE_WITH_METHODS` otherwise).
- Metrics:
  - `probe.plan`, including `numerical_rank`;
  - `probe.folds`: FIT/EVAL sample IDs, inner RMSE per component count, selection and train mean;
  - `probe.oof_predictions`, `probe.rmse`, `probe.mae`;
  - `probe.r2_oof` (`1 − SSE/Σ(y − ȳ_eval)²`), `undefined` for constant evaluation targets;
  - `probe.skill_vs_train_mean` (`1 − SSE_model/SSE_fold_train_mean` on the same rows), `undefined` when the baseline error is zero;
  - `probe.train_mean_rmse`, `probe.train_mean_mae`, and `probe.domain_scores` (per structured domain).

  There is no interval, because folds are not independent observations. Every metric publishes `numerical_domain`.
- Numerical domain (rule 13). The kernels accept finite values, every nonzero |x| in [2^-256, 2^256], and a spread of at most 2^64 per input array. Outside it, Methods refuses before computing, and the probe is `unsupported` with `NUMERICAL_DOMAIN_EXCEEDED`. Inside it, the Methods NIPALS PLS estimator refuses strongly scaled data (about X·2^±30 and beyond) with an explicit `NumericalFailure`, because its thresholds are absolute `DBL_EPSILON`. The probe then reports an `error` with context; this is a known upstream limit, never a wrong value.
- Finding. Skill ≤ 0 emits `probe.no_skill_over_train_mean.v1` (info, confidence `unknown`). A weak probe does not show that every calibration is impossible.

The DAG seed is the shared `derive_seed` over the source, target and estimator. The current grouped folds are deterministic and do not consume it.

The independent golden (`crates/nirs4all-preflight/tests/fixtures/generate_probe_sklearn_v1.py`: scikit-learn 1.7.2, NumPy 2.2.6) has three cases: base, rank-deficient and technical repeats. On every case and both estimators, outer and inner folds, selected components and the numerical rank are identical. OOF predictions, fold-train means, scores and domain scores agree within 1e-7 relative, on CPU and in WASM.

Tampered provider results are all rejected without a new CV: non-minimal selections, ties resolved to more components, duplicate fold IDs, a wrong fit count, a negative RMSE, an R² of 42, and scores or OOF rows altered by 0.1 %. On a batch-confounded fixture, sample-level folds give skill above 0.9. Holding out batches as groups never splits a batch and gives skill below 0.2. Under CI, a missing `N4M_LIBRARY_PATH` fails these tests instead of skipping them.
