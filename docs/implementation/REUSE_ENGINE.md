# Engine reuse and current alpha boundary

The preflight Rust engine owns input validation, population selection, source and context separation, protocol orchestration, report status, and finding rules. It does not reimplement generic numerical methods.

| Capability | Owner | Alpha integration |
| --- | --- | --- |
| File parsing and joins | `nirs4all-formats` and `nirs4all-io` | Caller supplies aligned typed input. |
| PCA eigenvalues, scores and full spectral moments | `nirs4all-methods` | `MethodsProvider::pca`; exact full moments permit effective dimension with truncated scores. |
| Pooled repeatability and balanced ICC(1,1) | `nirs4all-methods` | `MethodsProvider::repeatability` on homogeneous technical contexts. Per-band mask and status retained. |
| Quantiles and descriptive numerical summary | `nirs4all-methods` | `MethodsProvider::summary`. |
| Independent nearest neighbors in PCA score space | `nirs4all-methods` | `MethodsProvider::nearest_neighbors`, excluding the declared independence group. |
| Global local X–Y contrast | `nirs4all-methods` | `MethodsProvider::local_contrast` receives exact targets, admissible neighbor indices and linked group IDs; Preflight owns eligibility and statuses. |
| Metadata–Y association statistics and permutation tests | `nirs4all-methods` | `MethodsProvider::association` (eta²/F or Cramér V/χ², log10 bound on distinct outcomes, seeded Monte Carlo p-value) and `MethodsProvider::holm_adjust`; per-level Y coverage via `summary`. Preflight builds units, the `PermutationPlan`, statuses, the Holm family and findings. |
| SNV view | `nirs4all-methods` | `MethodsProvider::snv` calls the existing SNV transform (row mean, population SD, ddof 0; the same operator as the WASM registry). |
| Smoothing-residual noise proxy | `nirs4all-methods` | `MethodsProvider::noise_proxy` reuses the Methods Savitzky–Golay engine; Preflight owns population, context split, axis-uniformity check and statuses. |
| Pairs within a declared tolerance | `nirs4all-methods` | `MethodsProvider::tolerance_pairs`; Preflight owns the view, context, physical-identity groups, partitions and findings. |
| HDBSCAN partition, membership, GLOSH, persistence, condensed tree | `nirs4all-methods` | `MethodsProvider::hdbscan` on the canonical PCA scores; Preflight owns eligibility, parameter policy, subsampling plan and findings. |
| Adjusted Rand index | `nirs4all-methods` | `MethodsProvider::adjusted_rand_index` on samples assigned in both partitions. |
| Cross-validation, preprocessing selection and OOF | `dag-ml` | Unavailable until a qualified validation provider can execute a complete probe. Preflight has no second CV loop. |
| Aggregate package facades | `nirs4all-core` | Separate upstream integration; this crate carries the implementation. |

The explicit `UnavailableMethodsProvider` lets callers validate and inspect population/target coverage without implying that unavailable numerical diagnostics were computed. Every unavailable metric has a status, reason, and null value. The report is marked `exploratory`; alpha thresholds have not been qualified. The CLI uses this provider unless a Methods library is selected by `--methods-library` or `N4M_LIBRARY_PATH`.

For structure, observations from the same physical object are averaged only inside one source, instrument and campaign when every repeated acquisition has a declared technical repetition type. Physical objects occurring in multiple contexts, or under multiple sample IDs, are excluded from this single-context PCA profile with counts reported. Unknown or biological repeat types remain excluded from PCA aggregation with counts reported; single observations remain eligible. Rows with masked bands are excluded from complete-case PCA and counted. Retained-test and augmented samples are excluded. Technical repeatability is computed separately for each repetition type, instrument and campaign. No silent imputation, interpolation, source concatenation or reference reconciliation occurs.

Identity linkage is validated before any Methods call, including transitive physical aliases, shared individuals and augmentation parents. Reference groups spanning development and retained-test populations are rejected. The current validator does not verify external fold plans because the DAG validation provider is not connected; that capability stays unavailable.


Metadata–target associations (`metadata_association.v1`) cover each declared categorical metadata column carried by the input contract (`instrument`, `campaign`) against each target. The population is the exact, internally consistent references of real development samples; retained-test, prediction and augmented references are counted and never read. Samples are merged into independence units by linked physical sample, declared unit (`independence_group` when the unit is `group`), `reference_group_id` and `individual_id`. Units are ordered by their smallest sample ID, then receive one vote each. Units with missing metadata are excluded and counted. Units whose target or metadata varies internally are also excluded from the descriptive effect, and they make the test `not_identifiable`. The descriptive effect (`association.metadata_target`) is reported whenever it is defined, with per-level Y summaries or class counts.

`association.metadata_target_test` carries a versioned `PermutationPlan` (`permutation_plan.v1`): null hypothesis, tested effect, statistic (`eta_squared` or `cramers_v_squared`), exchangeable unit and whether exchangeability was declared, restrictions (`none_single_block`), block sizes, reduced model (none), draw method, Methods PCG64 RNG, decimal-string seed and its derivation, the log10 bound on distinct admissible permutations, requested/executed counts, resolution, p-value convention `(1+b)/(1+B)` and tie tolerance. The only executable plan is uniform unit-label permutation over one block. It requires a declared independence unit and `options.exchangeable_units = true`. A target constant in the block, an unknown unit, a missing group, undeclared exchangeability, or target/metadata varying inside a unit returns `not_identifiable` with its reason code. No restricted, crossed or residual permutation is substituted.

The family is every identifiable metadata × target test of the report (`association.metadata_target_family`), with Holm at 5 %. A test is executed only if `max(1/(B+1), 1/distinct)` is at most `0.05/m`. Otherwise it is `insufficient_data` (`PERMUTATION_RESOLUTION_INSUFFICIENT`), carries no p-value, and enters Holm as p = 1. B = 999. Each test seed is `splitmix64_finalizer(options.seed XOR fnv1a64(domain))`, where the domain names provider, protocol, target and metadata. Seeds travel as decimal strings so JavaScript hosts never round them. A Holm rejection produces the exploratory finding `association.metadata_target.v1` with confidence `unknown`; it is not causal evidence.

The alpha integrity pass counts exact spectral pairs spanning declared physical samples after normalizing negative zero and honoring masks. It separately counts exact pairs across real development and retained-test observations under different physical IDs, with affected-observation denominators. This integrity check reads retained-test X only; it does not fit on test rows or inspect retained-test Y. Findings remain suspicions with unknown confidence. Exact matches never rewrite sample identity automatically.

Quasi-duplicates run only when `options.quasi_duplicates.tolerance` is declared (finite, positive, in the units of the chosen view); no default tolerance exists. Without it, `integrity.quasi_duplicate_pairs` and `integrity.cross_partition_quasi_duplicate_pairs` are `not_applicable` with `QUASI_DUPLICATE_TOLERANCE_NOT_DECLARED`, and the report's `quasi_duplicates` capability is unavailable with the same reason. The distance is the root-mean-square band difference in the declared view (`native` or SNV, reported as view `canonical:snv`) and context (`instrument_campaign`, the default; `instrument`, which pairs observations of one instrument across its campaigns; or `source`). Observations without a declared instrument or campaign share one context, which the metric states. Populations follow the exact pass: complete-case real development rows, pairs inside one physical sample excluded, and a separate development × retained-test comparison that reads retained-test X only. Each metric reports tolerance and unit, candidate and suspect pair counts, suspect-pair rate, affected-observation fractions and up to 1,000 listed pairs. Exact duplicates are included. Findings `identity.possible_quasi_duplicate_repeats.v1` (warning) and `identity.possible_cross_partition_quasi_duplicate.v1` (high) carry unknown confidence and never rewrite identities. Each listed pair carries descriptive `concordant_indices`: same instrument, campaign, `individual_id` and `independence_group` (true/false when both sides declare the key, null otherwise) and, for development pairs only, per target whether the exact eligible references are identical and share `reference_id` / `reference_group_id`. Development × retained-test pairs never compare references (`reference_comparison: not_performed_retained_test_Y_never_read`). The concordant indices are columns of the listed pairs only; they are not aggregated over unlisted pairs.

Spectral duplicates with incompatible references (`duplicate_reference_conflicts`, spec §5.5) are pure comparisons of declared values in Rust; no Methods kernel is involved beyond the pair search above. They run only for targets named in `options.reference_contradiction_tolerances`: `{"kind":"absolute","value":v}` (incompatible when |y_a − y_b| > v, target units) or `{"kind":"relative","value":v}` (incompatible when |y_a/m − y_b/m| > v with m = max(|y_a|, |y_b|), and compatible when m = 0; the normalized form cannot overflow, unlike v·m, so 1.7e308 against −1.7e308 at v = 1.5 is a conflict) for continuous targets, `{"kind":"different_class"}` for categorical ones. Values must be finite and positive; an unknown target or a kind that does not match the target is a blocking validation issue. No tolerance is ever derived from data or lab precision. An undeclared target gives `not_applicable` with `REFERENCE_CONTRADICTION_TOLERANCE_NOT_DECLARED`. An absolute difference that cannot be represented exceeds every finite tolerance and is listed as null. Three metrics use the same rule:

- `reference.within_physical_sample_conflicts` (per target): pairs of sample IDs that declare the same `physical_sample_id`, i.e. aliases of one object. One object has one reference value, so no spectral evidence is required. This population is checked before, and separately from, the presumed repeats between objects, which the pair searches below exclude by physical identity.

- `reference.exact_duplicate_conflicts` (per source × target): the pairs of the exact pass (whole source, normalized float bits and mask sentinel, real development rows under different physical samples);
- `reference.quasi_duplicate_conflicts`: every development pair of `integrity.quasi_duplicate_pairs` in its view and context. Beyond the 1,000 listed pairs, Preflight asks Methods once more for the complete pair list of that context. It inherits the quasi-duplicate status and reason when that metric is unavailable, and its parameters name the spectral tolerance `spectral_tolerance` to keep it apart from the contradiction tolerance.

Pairs are reduced to unordered sample pairs: one comparison per sample pair, whatever the number of acquisitions. Only exact, internally consistent references of real development samples are compared (the population of `target.exact_eligible_samples`). Censored, composite, inconsistent and missing references are not compared and are counted in `n_sample_pairs_without_two_exact_references`. Retained-test Y is never read. A sample's admissible references are all its exact, consistent development references. They share one value, and their `reference_id` and `reference_group_id` values are kept as sets. `shared_reference_id` and `shared_reference_group_id` in the concordant indices are true when the two sets intersect, false when both are non-empty and disjoint, and null otherwise. This makes them independent of measurement order. Denominators separate `n_development_observations` (every real development observation of the source), `n_admissible_development_observations` (the population of the pair search: at least one valid cell for the exact pass, complete rows for the quasi pass) and `n_excluded_development_observations`. `fraction_denominators` names the denominator of each fraction. The value reports suspect, compared and incompatible sample pairs, the incompatible rate among compared pairs, affected samples (fraction of the development samples of the population that have an exact reference), affected development observations (those in an incompatible pair, fraction of the population rows), and up to 1,000 incompatible pairs with both references, reference IDs, the absolute difference and the smallest RMS difference. More than 1,000,000 retained development pairs gives `unsupported` with `SUSPECT_PAIR_BUDGET_EXCEEDED`; the X-side counts stay. A conflict produces the finding `reference.verify_reference_or_pairing.v1` (warning, confidence unknown): verify reference and pairing; nothing is removed.

`measurement.noise_proxy` (per band) and `measurement.noise_proxy_pooled` are computed per instrument × campaign on native real development acquisitions with equal weight. They are the root mean square of the Savitzky–Golay smoothing residual (default 11 bands, polyorder 2, configurable in `options.noise_proxy`) divided by the filter's white-noise residual gain. The window must be odd in [3, 1001] and the polyorder at most min(10, window − 2): Methods verified that domain to reproduce polynomial moments, and outside it the weights do not smooth as requested (window 41 / order 38 gave a residual of 0.83 on a constant row). The fields are u64 and validated without arithmetic that could wrap, so 32-bit WASM and 64-bit hosts reject the same inputs with `INVALID_NOISE_PROXY_PARAMETERS`. Only interior bands are evaluated; there is no padding at the edges. A window containing a masked cell is skipped. The axis must be uniform within 10⁻³ of its mean spacing (`NON_UNIFORM_AXIS` otherwise). Window, physical width, normalization, edge and mask behavior and the assumption (locally polynomial signal, white noise) are declared parameters. The label is `noise_proxy_not_snr`; no SNR is produced.

`structure.snv_sensitivity` is on by default (`options.snv_sensitivity: false` disables it). SNV is applied to each acquisition of the canonical PCA population. The result is then aggregated with the same sample means and decomposed with the same number of components, as view `canonical:snv_centered`. The metric reports, for both views, eigenvalue shares of the full variance trace, the first-component and retained shares, the full-moment effective dimension, and the differences between the two views. `structure.snv_pca_eigenvalues` and `structure.snv_effective_dimension` give the SNV view itself. The comparison is descriptive and makes no attribution to nuisance or chemistry. Constant acquisitions map to exact zeros in the Methods SNV. The SNV view also has a numerical-rank criterion built from Methods' error bounds. `n4m_preflight_snv_compute` returns, for each acquisition i, a first-order bound B_i on the rounding error of every SNV entry. It accounts for the row mean, the summation error and the SD: `(u(|m| + A) + 4 n u² max|y|)/sd_y + 8 u max|z|`, on power-of-two rescaled values with compensated sums. If the analytic SNV rows were identical, the per-band RMS deviation of the aggregated rows would stay below 2√2·max B, plus the PCA column-mean rounding n·u·max|z|. The residual variance therefore counts as resolved only if `sqrt(trace(C_snv)/p) > 4·(max_i B_i + n·u·max|z|)`. Otherwise `structure.snv_effective_dimension` and `structure.snv_sensitivity` are `undefined` with `SNV_VARIANCE_NOT_NUMERICALLY_RESOLVED`. All three SNV metrics publish `snv_total_variance`, `snv_rms_band_deviation`, `numerical_resolution_threshold`, `max_snv_entry_error_bound`, the criterion and `numerically_resolved`. The review examples give these values:

- rows `a·[1..5]+b`: RMS deviation 1.4e-15 for a threshold of 3.7e-14;
- the same offsets over 100,000 bands: 9.5e-14 for a threshold of 1.5e-11. The earlier SNV mean left 2.7e-8 there.

The JSON input and report schemas are version 1. Internal Methods adapter contracts are Rust structs in `nirs4all-preflight-core/src/lib.rs`; host adapters must validate native shapes, finite numbers, and ABI versions before returning values. C API, WASM and language bindings must call this same engine, never duplicate the protocol.

PCA reports scores with actual representative declared sample IDs and separate aggregation keys inline up to 100,000 score cells, full variance moments, and retained explained-variance fraction. The inline limit is an explicit alpha report budget; a future asset transport is needed for larger score tables. A zero-rank source has undefined PCA geometry and local contrast. Input and report carry an optional `data_origin` label, including `synthetic` for demonstrations. The HTML export prints audit context and summarizes large arrays; JSON remains the complete scientific record.

Clustering (PF-05, exploratory, unqualified) uses the same eligible aggregated samples and canonical PCA scores as `structure.*`, in their canonical BTreeMap order. HDBSCAN results depend on row order and tie order, so that order is part of the protocol. The policy is frozen as follows:

- Parameters: `min_cluster_size = min_samples = max(5, ceil(n/20))`, where `min_samples` includes the sample itself, with EOM selection and `allow_single_cluster = false`. Fewer than `2 × min_cluster_size` eligible samples gives `FEWER_THAN_TWO_MIN_CLUSTER_SIZES`.
- Subsampling: 50 seeded subsamples without replacement of `ceil(0.8 × U)` independent units. A unit is the eligible physical sample, or the declared `independence_group` when `independence_unit = group`; a missing group gives `MISSING_INDEPENDENCE_GROUP`. The RNG is SplitMix64 seeded with `seed xor fnv1a64(source_id)`, followed by a partial Fisher–Yates shuffle.
- Refit: each subsample repeats centering, PCA (`min(10, m-2, p)` components) and HDBSCAN on the aggregated spectra. It does this twice: with `ceil(0.8 × parameter)` (floors 2 and 1), and with the constant full-sample parameters as a sensitivity variant.
- Comparison: on common sample identities against the full partition. ARI is computed only on samples assigned in both partitions, when at least 10 such samples exist and both partitions have two clusters there. Methods summarizes the distributions of ARI, assigned/noise agreement, cluster count, noise fraction, intersection size and compared fraction.
- Budget: work above `50 × n² × (p + 20) = 2.5e10` gives `STABILITY_WORK_BUDGET_EXCEEDED`.

Two protocol parts are not delivered yet and are reported as unavailable: cluster appearance frequency (`CLUSTER_MATCHING_NOT_QUALIFIED`) and the Gaussian null model (`NULL_MODEL_NOT_IMPLEMENTED`). Findings are `structure.clustering.uncertain_partition.v1` or `structure.clustering.continuous_structure.v1`, both with confidence `unknown`. They never state a firm number of clusters, and membership is labelled as a relative strength, not a probability. On a 60-sample three-blob input, native and WASM gave identical labels, counts and denominators, with numeric values within 1.3e-15 relative. Because HDBSCAN breaks exact ties, last-ulp PCA differences between hosts could still flip a near-tie on other data, so cross-host partition parity is not claimed beyond such checks.
