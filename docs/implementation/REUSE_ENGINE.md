# Engine reuse and current alpha boundary

The preflight Rust engine owns input validation, population selection, source and context separation, protocol orchestration, report status, and finding rules. It does not reimplement generic numerical methods.

| Capability | Owner | Alpha integration |
| --- | --- | --- |
| File parsing and joins | `nirs4all-formats` and `nirs4all-io` | Caller supplies aligned typed input. |
| PCA eigenvalues, scores and full spectral moments | `nirs4all-methods` | `MethodsProvider::pca`; exact full moments permit effective dimension with truncated scores. |
| Pooled repeatability and balanced ICC(1,1) | `nirs4all-methods` | `MethodsProvider::repeatability` on homogeneous technical contexts. Per-band mask and status retained. |
| Quantiles and descriptive numerical summary | `nirs4all-methods` | `MethodsProvider::summary`. |
| Independent nearest neighbors in PCA score space | `nirs4all-methods` | `MethodsProvider::nearest_neighbors`, excluding the declared independence group. |
| Global local X–Y contrast | `nirs4all-methods` | `MethodsProvider::local_contrast` receives exact targets, admissible neighbor indices and linked group IDs; Preflight owns eligibility and statuses. |
| Metadata–Y association statistics and permutation tests | `nirs4all-methods` | `MethodsProvider::association` (eta²/F or Cramér V/χ², log10 bound on distinct outcomes, seeded Monte Carlo p-value) and `MethodsProvider::holm_adjust`; per-level Y coverage via `summary`. Preflight builds units, the `PermutationPlan`, statuses, the Holm family and findings. |
| SNV view | `nirs4all-methods` | `MethodsProvider::snv` calls the existing SNV transform (row mean, population SD, ddof 0; the same operator as the WASM registry). |
| Smoothing-residual noise proxy | `nirs4all-methods` | `MethodsProvider::noise_proxy` reuses the Methods Savitzky–Golay engine; Preflight owns population, context split, axis-uniformity check and statuses. |
| Pairs within a declared tolerance | `nirs4all-methods` | `MethodsProvider::tolerance_pairs`; Preflight owns the view, context, physical-identity groups, partitions and findings. |
| HDBSCAN partition, membership, GLOSH, persistence, condensed tree | `nirs4all-methods` | `MethodsProvider::hdbscan` on the canonical PCA scores; Preflight owns eligibility, parameter policy, subsampling plan and findings. |
| Adjusted Rand index | `nirs4all-methods` | `MethodsProvider::adjusted_rand_index` on samples assigned in both partitions. |
| Cluster Jaccard matrix and one-to-one assignment | `nirs4all-methods` | `MethodsProvider::cluster_jaccard` and `MethodsProvider::linear_sum_assignment` (SciPy 1.18.1 port); Preflight owns the matching rule, threshold and appearance counts. |
| Subsampling plans and Gaussian draws | `nirs4all-methods` | `MethodsProvider::random_permutations` and `MethodsProvider::multivariate_normal` on PCG64 with NumPy-identical streams; Preflight derives the seeds and builds units, plans and the null protocol. |
| Cross-validation, preprocessing selection and OOF | `dag-ml` | Unavailable until a qualified validation provider can execute a complete probe. Preflight has no second CV loop. |
| Aggregate package facades | `nirs4all-core` | Separate upstream integration; this crate carries the implementation. |

The explicit `UnavailableMethodsProvider` lets callers validate and inspect population/target coverage without implying that unavailable numerical diagnostics were computed. Every unavailable metric has a status, reason, and null value. The report is marked `exploratory`; alpha thresholds have not been qualified. The CLI uses this provider unless a Methods library is selected by `--methods-library` or `N4M_LIBRARY_PATH`.

For structure, observations from the same physical object are averaged only inside one source, instrument and campaign when every repeated acquisition has a declared technical repetition type. Physical objects occurring in multiple contexts, or under multiple sample IDs, are excluded from this single-context PCA profile with counts reported. Unknown or biological repeat types remain excluded from PCA aggregation with counts reported; single observations remain eligible. Rows with masked bands are excluded from complete-case PCA and counted. Retained-test and augmented samples are excluded. Technical repeatability is computed separately for each repetition type, instrument and campaign. No silent imputation, interpolation, source concatenation or reference reconciliation occurs.

Identity linkage is validated before any Methods call, including transitive physical aliases, shared individuals and augmentation parents. Reference groups spanning development and retained-test populations are rejected. The current validator does not verify external fold plans because the DAG validation provider is not connected; that capability stays unavailable.


Metadata–target associations (`metadata_association.v1`) cover each declared categorical metadata column carried by the input contract (`instrument`, `campaign`) against each target. The population is the exact, internally consistent references of real development samples; retained-test, prediction and augmented references are counted and never read. Samples are merged into independence units by linked physical sample, declared unit (`independence_group` when the unit is `group`), `reference_group_id` and `individual_id`. Units are ordered by their smallest sample ID, then receive one vote each. Units with missing metadata are excluded and counted. Units whose target or metadata varies internally are also excluded from the descriptive effect, and they make the test `not_identifiable`. The descriptive effect (`association.metadata_target`) is reported whenever it is defined, with per-level Y summaries or class counts.

`association.metadata_target_test` carries a versioned `PermutationPlan` (`permutation_plan.v1`): null hypothesis, tested effect, statistic (`eta_squared` or `cramers_v_squared`), exchangeable unit and whether exchangeability was declared, restrictions (`none_single_block`), block sizes, reduced model (none), draw method, Methods PCG64 RNG, decimal-string seed and its derivation, the log10 bound on distinct admissible permutations, requested/executed counts, resolution, p-value convention `(1+b)/(1+B)` and tie tolerance. The only executable plan is uniform unit-label permutation over one block. It requires a declared independence unit and `options.exchangeable_units = true`. A target constant in the block, an unknown unit, a missing group, undeclared exchangeability, or target/metadata varying inside a unit returns `not_identifiable` with its reason code. No restricted, crossed or residual permutation is substituted.

The family is every identifiable metadata × target test of the report (`association.metadata_target_family`), with Holm at 5 %. A test is executed only if `max(1/(B+1), 1/distinct)` is at most `0.05/m`. Otherwise it is `insufficient_data` (`PERMUTATION_RESOLUTION_INSUFFICIENT`), carries no p-value, and enters Holm as p = 1. B = 999. Each test seed is `splitmix64_finalizer(options.seed XOR fnv1a64(domain))`, where the domain names provider, protocol, target and metadata. Seeds travel as decimal strings so JavaScript hosts never round them. A Holm rejection produces the exploratory finding `association.metadata_target.v1` with confidence `unknown`; it is not causal evidence.

The alpha integrity pass counts exact spectral pairs spanning declared physical samples after normalizing negative zero and honoring masks. It separately counts exact pairs across real development and retained-test observations under different physical IDs, with affected-observation denominators. This integrity check reads retained-test X only; it does not fit on test rows or inspect retained-test Y. Findings remain suspicions with unknown confidence. Exact matches never rewrite sample identity automatically.

Quasi-duplicates run only when `options.quasi_duplicates.tolerance` is declared (finite, positive, in the units of the chosen view); no default tolerance exists. Without it, `integrity.quasi_duplicate_pairs` and `integrity.cross_partition_quasi_duplicate_pairs` are `not_applicable` with `QUASI_DUPLICATE_TOLERANCE_NOT_DECLARED`, and the report's `quasi_duplicates` capability is unavailable with the same reason. The distance is the root-mean-square band difference in the declared view (`native` or SNV, reported as view `canonical:snv`) and context (`instrument_campaign`, the default, or `source`). Populations follow the exact pass: complete-case real development rows, pairs inside one physical sample excluded, and a separate development × retained-test comparison that reads retained-test X only. Each metric reports tolerance and unit, candidate and suspect pair counts, suspect-pair rate, affected-observation fractions and up to 1,000 listed pairs. Exact duplicates are included. Findings `identity.possible_quasi_duplicate_repeats.v1` (warning) and `identity.possible_cross_partition_quasi_duplicate.v1` (high) carry unknown confidence and never rewrite identities.

`measurement.noise_proxy` (per band) and `measurement.noise_proxy_pooled` are computed per instrument × campaign on native real development acquisitions with equal weight. They are the root mean square of the Savitzky–Golay smoothing residual (default 11 bands, polyorder 2, configurable in `options.noise_proxy`) divided by the filter's white-noise residual gain. Only interior bands are evaluated; there is no padding at the edges. A window containing a masked cell is skipped. The axis must be uniform within 10⁻³ of its mean spacing (`NON_UNIFORM_AXIS` otherwise). Window, physical width, normalization, edge and mask behavior and the assumption (locally polynomial signal, white noise) are declared parameters. The label is `noise_proxy_not_snr`; no SNR is produced.

`structure.snv_sensitivity` is on by default (`options.snv_sensitivity: false` disables it). SNV is applied to each acquisition of the canonical PCA population. The result is then aggregated with the same sample means and decomposed with the same number of components, as view `canonical:snv_centered`. The metric reports, for both views, eigenvalue shares of the full variance trace, the first-component and retained shares, the full-moment effective dimension, and the differences between the two views. `structure.snv_pca_eigenvalues` and `structure.snv_effective_dimension` give the SNV view itself. The comparison is descriptive and makes no attribution to nuisance or chemistry.

The JSON input and report schemas are version 1. Internal Methods adapter contracts are Rust structs in `nirs4all-preflight-core/src/lib.rs`; host adapters must validate native shapes, finite numbers, and ABI versions before returning values. C API, WASM and language bindings must call this same engine, never duplicate the protocol.

PCA reports scores with actual representative declared sample IDs and separate aggregation keys inline up to 100,000 score cells, full variance moments, and retained explained-variance fraction. The inline limit is an explicit alpha report budget; a future asset transport is needed for larger score tables. A zero-rank source has undefined PCA geometry and local contrast. Input and report carry an optional `data_origin` label, including `synthetic` for demonstrations. The HTML export prints audit context and summarizes large arrays; JSON remains the complete scientific record.

Clustering (PF-05, protocol `clustering.v3`, exploratory, unqualified) uses the same eligible aggregated samples and canonical PCA scores as `structure.*`, in their canonical BTreeMap order. HDBSCAN results depend on row order and tie order, so that order is part of the protocol. The policy is frozen as follows:

- Parameters: `min_cluster_size = min_samples = max(5, ceil(n/20))`, where `min_samples` includes the sample itself, with EOM selection and `allow_single_cluster = false`. Fewer than `2 × min_cluster_size` eligible samples gives `FEWER_THAN_TWO_MIN_CLUSTER_SIZES` for every clustering metric.
- Score grid: every score matrix passed to HDBSCAN (full, subsample and null) is rounded half away from zero to multiples of `2^(e−24)`, where `max|score|` lies in `[2^(e−1), 2^e)`. Power-of-two steps make the rounding exact on every host. Without it, last-ulp PCA differences between native and WASM (4.4e-16 on the review case) changed near-tied mutual-reachability orders and gave 7 versus 8 groups. Residual risk, pinned by a unit test: a score one ulp below a grid midpoint rounds down while the midpoint and one ulp above round up, so a one-ulp host difference there moves the score by one grid step; likewise a `max|score|` one ulp either side of a power of two changes the step by a factor of two. With host differences of the order of 4e-16 relative, a given score lies that close to a midpoint with probability of the order of 1e-8. Cross-host parity is therefore pinned by goldens and explicitly not guaranteed for such values; the partition parameters say so (`cross_host_parity`). Reported tree distances are in grid-rounded score units.
- Resampling units: rows are merged by shared `individual_id` and, according to `independence_unit`, by `independence_group` (`group`; missing gives `MISSING_INDEPENDENCE_GROUP`) or by the reference group (`reference_group`). A row's reference group is the single `reference_group_id` carried by its references over all targets, whatever their status; no group gives `MISSING_REFERENCE_GROUP` and several give `AMBIGUOUS_REFERENCE_GROUP`, both `not_identifiable`. Y values are never read. `sample` keeps one unit per physical sample. `unknown` resamples rows as a descriptive sensitivity only, reported as `resampling_unit = eligible_sample_undeclared_independence` and `independent_unit_resampling = false`; it can never yield a stable-partition assessment. Fewer than five units gives `FEWER_THAN_FIVE_RESAMPLING_UNITS`. Units are ordered by their first eligible row.
- Plans: one Methods PCG64 stream, `n4m_random_permutations`, equal to `numpy.random.default_rng(seed).permutation(U)` drawn 50 times. Subsample `b` keeps the units `sorted(permutation_b[0:ceil(0.8 U)])`. The seed is `splitmix64_finalizer(root_seed XOR fnv1a64("nirs4all-preflight\0methods\0clustering.v3\0subsample_plans\0" + source_id))` and travels as a decimal string. The same 50 plans serve both parameter variants and the null model; the unit plans and each unit's first row are published in `clustering.subsample_stability`.
- Refit: each subsample repeats centering, PCA (`min(10, m−2, p)` components), the score grid and HDBSCAN on the aggregated spectra, once with `ceil(0.8 × parameter)` (floors 2 and 1) and once with the constant full-sample parameters (`clustering.subsample_stability_constant_parameters`).
- Comparison: every drawn identity is common to both partitions. Each subsample reports the intersection size, the size of the identities assigned to a cluster in both partitions, its ARI (only with at least 10 such identities and two clusters in both partitions on them), cluster count, noise fraction and assigned/noise agreement. Summaries separate the intersection fraction of eligible samples from the assigned-in-both fraction, and give the ARI population size and its fractions of eligible samples and of the intersection over exactly the ARI-evaluable subsamples.
- Budget: `50 × n² × (p + 20) > 2.5e10` gives `STABILITY_WORK_BUDGET_EXCEEDED`.

Cluster appearance frequency (`cluster_matching.v1`, one metric per parameter variant): in each subsample, each reference cluster restricted to the drawn identities is compared with each subsample cluster by Jaccard (Methods `n4m_cluster_jaccard_matrix`; noise is in no cluster). A one-to-one assignment maximizing total Jaccard is computed by Methods `n4m_linear_sum_assignment`, the SciPy 1.18.1 `linear_sum_assignment` port with its tie order, with reference labels as rows and subsample labels as columns in ascending order. An unmatched reference cluster has Jaccard 0. A cluster appears when its matched Jaccard is above 0.5; a subsample is evaluable for a cluster when at least one of its members was drawn. Each cluster reports evaluable and appearance counts, the appearance frequency, and summaries of the matched Jaccard and of the drawn member fraction. Without reference clusters the metric is `not_applicable` (`NO_REFERENCE_CLUSTERS`).

Gaussian null model (`clustering.gaussian_null_model`): a unimodal Gaussian with zero mean and covariance `diag(λ) + 1e-6 × mean(λ) × I`, where `λ` are the Methods PCA eigenvalues (ddof 1) of the canonical scores, which are centered and uncorrelated. Each of B = 99 replicates draws `n` independent rows with Methods `n4m_random_multivariate_normal` (NumPy `multivariate_normal(..., method="cholesky")` on PCG64) from a seed derived per replicate (`...\0gaussian_null\0` + source_id + `\0` + b).

- Same protocol on both sides, frozen projection: the observed canonical scores and each replicate's simulated scores are subsampled with the same 50 plans without any PCA refit, rounded to the score grid and clustered with the scaled parameters; full partitions use the full-sample parameters. The refit stability metrics stay reported but are not compared with the null, because the observed refits start from `p` bands while the null only has the `d` retained components.
- Pre-specified statistic: the coverage-weighted stability, the median over the 50 subsamples of `ARI × (assigned in both / drawn)`, with 0 when ARI is not evaluable. Its exploratory fitted-null tail fraction is `(1 + #{T_b ≥ T_obs})/(1 + B)`, ties counting against the observation, resolution 0.01 (`fitted_null_tail`). It is **not** an exact Monte Carlo test: the Gaussian (PCA eigenvalues, retained dimension) is estimated from the same data, so the observed and simulated statistics are not exchangeable and no type-I error level is guaranteed. Even a valid test would only concern an excess of this stability over this one fitted model. The qualification path, declared in the parameters, is a parametric bootstrap that re-estimates the PCA and the Gaussian in every simulated dataset, with the level of the resulting rule checked by simulation.
- Decisional scope: simulated rows are independent, so the test decides only when every resampling unit is one row with a declared independence unit. With multi-row units (`MULTI_ROW_RESAMPLING_UNITS`), undeclared units (`INDEPENDENCE_UNIT_UNDECLARED`), no plans or the null stability over budget, it is descriptive only. A grouped null (simulated unit centres plus within-unit deviations) was not chosen: the within-unit structure of aggregated spectra in a lot or group is not known to be Gaussian, and simulating it would add an unvalidated model to the decision.
- Descriptive only: per-replicate cluster counts, noise fractions, statistics and median ARIs, marginal tails `(1 + #null ≥ observed)/(1 + B)` and `(1 + #null ≤ observed)/(1 + B)`, and the number of replicates dominating on cluster count, noise and statistic. A joint dominance tail is not a 5 % tail and no longer drives any verdict.
- Budget: the null is `unsupported` when `99 × n² × (d + 20)` exceeds 2.5e10, and its stability part (hence the test) is skipped when `99 × 51 × n² × (d + 20)` does. The parameters state that the model is one unimodal Gaussian and does not represent curved or branched manifolds, gradients, heavy tails or heteroscedastic continua.

Assessment (`clustering.partition_assessment`, rule `clustering_assessment.v3`, thresholds declared and not validated) publishes each criterion with its value, threshold and outcome: fewer than two groups gives `no_density_separated_groups`; a decisional fitted-null tail fraction above 0.05 gives `compatible_with_fitted_gaussian`; otherwise `stable_candidate_versus_fitted_gaussian` requires declared independent units, median refit ARI ≥ 0.8 under both parameter variants, every scaled appearance frequency ≥ 0.8, a median assigned-in-both fraction of eligible samples ≥ 0.5, a decisional null and a tail fraction ≤ 0.05; anything else is `uncertain_partition`. Verdict names and findings (`structure.clustering.continuous_structure.v3`, `structure.clustering.stable_candidate_partition.v2`, `structure.clustering.uncertain_partition.v3`) say that the comparison is with a Gaussian fitted to the same data and carries no type-I error guarantee; all have confidence `unknown` and never state a firm number of clusters. Native, canonical and supervised structures are not compared: only the canonical view is clustered, and this alpha has no supervised latent space.

The full chain is pinned by `crates/nirs4all-preflight/tests/fixtures/clustering_v3_golden.json`, written by `scripts/generate_clustering_golden.py`: an independent NumPy 2.4.6 / SciPy 1.18.1 / scikit-learn 1.9.1 implementation of the protocol with the Methods stable MST tie order. Seven datasets cover the first review's tie-heavy case with undeclared units, another tie-heavy case, separated blobs, a Gaussian continuum with single-row reference groups, the second review's 12 unit centres × 5 near-identical rows declared as groups, 20 bands of similar variance (no groups) and three blobs in 15 bands. The native and WASM engines reproduce the partitions up to label permutation, the 50 PCG64 unit plans, every subsample comparison, the appearance counts, the 99 null replicates, the observed statistic, the fitted-null tail fraction, the decisional flag and the assessments; real values agree within 1e-12. The grouped case is `uncertain_partition` with a non-decisional null, where the previous rule accepted it as stable.

Numerical domain (rules 13/15): the Methods clustering kernels accept finite inputs with every nonzero `|x|` in `[2^-256, 2^256]` and max/min nonzero `|x|` `≤ 2^32` (Methods macros `N4M_DOMAIN_MAX_MAGNITUDE_LOG2`, `N4M_DOMAIN_MAX_SPREAD_LOG2`), and refuse anything else before computing. The native adapter and the WASM bridge turn that refusal into the reason `NUMERICAL_DOMAIN_EXCEEDED` (metric status `unsupported`), and every clustering metric publishes the domain in `numerical_domain`. Because HDBSCAN receives grid-rounded scores, whose nonzero values span at most `2^24` below the largest, only magnitudes beyond `2^±256` can reach the refusal; at those scales the upstream PCA fails first today.

Robustness: the score grid is exactly scale-equivariant (scaling by `2^k` scales the rounded scores by `2^k` while the step is normal; unit test over `k ∈ {−1014, …, 1000}`), the null ridge uses an overflow-free mean of the eigenvalues, and every Methods kernel used here (HDBSCAN, Jaccard, assignment, ARI, Gaussian draws) states its domain of validity and either keeps its scale invariances or returns an explicit error. The engine-level sweep (`native_clustering_magnitude_sweep`) scales the blob golden by `2^k`: the partition is unchanged for `k = ±100`, and for `|k| ≥ 500`, `k ≤ −1014` and a constant `1e300` band the upstream Methods PCA reports an error or `ZERO_NUMERICAL_RANK`, so clustering stays unavailable with that reason. The tiny-scale `ZERO_NUMERICAL_RANK` is a PCA moment underflow outside this module and is reported upstream.
