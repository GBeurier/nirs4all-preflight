# Engine reuse and current alpha boundary

The preflight Rust engine owns input validation, population selection, source and context separation, protocol orchestration, report status, and finding rules. It does not reimplement generic numerical methods.

The explicit `UnavailableMethodsProvider` lets callers validate and inspect population/target coverage without implying that unavailable numerical diagnostics were computed. Every unavailable metric has a status, reason, and null value. The report is marked `exploratory`; alpha thresholds have not been qualified. The CLI uses this provider unless a Methods library is selected by `--methods-library` or `N4M_LIBRARY_PATH`.

For structure, observations from the same physical object are averaged only inside one source, instrument and campaign when every repeated acquisition has a declared technical repetition type. Physical objects occurring in multiple contexts, or under multiple sample IDs, are excluded from this single-context PCA profile with counts reported. Unknown or biological repeat types remain excluded from PCA aggregation with counts reported; single observations remain eligible. Rows with masked bands are excluded from complete-case PCA and counted. Retained-test and augmented samples are excluded. Technical repeatability is computed separately for each repetition type, instrument and campaign. No silent imputation, interpolation, source concatenation or reference reconciliation occurs.

Identity linkage is validated before any Methods call on whole linked components of the original rows: physical samples, individuals, augmentation parents, declared `independence_group` (always, whatever the analysis unit) and reference groups. Prediction rows take no partition role but remain identity bridges, so a development row linked to a retained-test row through a prediction row is refused (`IDENTITY_LEAKAGE`, or `REFERENCE_LEAKAGE` when only reference groups close the component). Retained-test target content is never decoded: input JSON is parsed with partitions and identifiers first, target `value` and `category` are held as unparsed JSON text (`serde_json` `RawValue`, which the tokenizer only skips), and a retained-test reference keeps its identity fields while its value and category are dropped unread, whatever their JSON text (including tokens such as `1e400` that a typed parser rejects); development values keep their typed check. Identity components use structured keys (`IdentityKey`: sample, physical, individual, group, and (target, reference group)), so identifiers containing separators never collide; the local-contrast neighbor groups use the same keys. The WASM runtime also exposes `analyzeJson`/`validateJson`, which hand the JSON text to Rust unchanged. Fold plans returned by the validation provider are checked against these components before any score is reported (see the probe paragraph below).


Typed metadata. The input carries an optional `metadata` table (schema version 1, optional fields only): `columns` declare a `name`, a `kind` (`categorical` or `continuous`) and, for continuous columns, a `unit`; `values` map `sample_id` → column → value, where a JSON string is a categorical level, a JSON number a continuous value, and absent or `null` means missing. Metadata are sample-level because `instrument` and `campaign` already are and because association units are built from samples; an acquisition-level covariate (for example a per-scan temperature) can be declared only when it is constant for the sample. Validation is blocking for an empty, duplicated or reserved name (`instrument`, `campaign`), a unit on a categorical column or an empty unit (`INVALID_METADATA_COLUMN`), an undeclared sample (`UNKNOWN_SAMPLE`), an undeclared column (`UNKNOWN_METADATA_COLUMN`), a string for a continuous column or a number for a categorical one (`METADATA_TYPE_MISMATCH`, nothing is converted) and an empty level or non-finite value (`INVALID_METADATA_VALUE`). It warns, without blocking, for a continuous column without unit (`UNKNOWN_METADATA_UNIT`) and for a column whose values differ inside a linked identity component (`METADATA_VARIES_WITHIN_INDEPENDENCE_UNIT`). `QualificationInput::metadata_factors()` returns the analysable factors in report order (`instrument`, `campaign`, then declared columns) with name, kind, unit and origin (`sample_field` or `declared`); `QualificationInput::metadata_value(&factor, &sample)` returns `MetadataLevel::Category(&str)` or `MetadataLevel::Value(f64)`, or `None` when missing. Other protocols (confounding) read metadata only through these two functions.

Metadata–target associations (`metadata_association.v1`) test every factor against every target. The population is the exact, internally consistent references of real development samples; retained-test, prediction and augmented references are counted and their Y is never read, not even by input validation (which checks the partition before any Y content). Independence units are the identity components of all samples, built by `independence_components` from every identity and reference link before any analytic exclusion: physical sample, individual, augmentation parent, `independence_group` when the unit is `group`, and the `reference_group_id` of every reference of the target, whatever its partition, status or position in the input. Eligible references are then grouped by component, ordered by their smallest sample ID, and receive one vote each. Units with missing metadata are excluded and counted. Units whose target or metadata varies internally are excluded from the descriptive effect and make the test `not_identifiable`; when these exclusions leave fewer than two levels or three units, the structural reason is reported instead of `SINGLE_METADATA_LEVEL`. The statistic follows the types: categorical metadata use eta² and ANOVA F (continuous target) or Cramér V and Pearson χ² (categorical target), with per-level Y summaries or class counts; continuous metadata use eta² and F of the metadata across target classes (categorical target, per-class metadata summaries; the kernel permutes metadata values across units, which is equivalent in law to permuting target labels), or Spearman's rho on average ranks with Pearson's r as a descriptive companion (continuous target; two-sided test on |rho|). Spearman is the tested statistic because it is invariant to monotone transformations of covariates such as temperature and robust to isolated extreme values. A continuous column with one value is `not_applicable` (`CONSTANT_METADATA_VALUE`).

Numerical domain (rules 13 and 15). The Methods association, correlation and exact kernels accept finite values whose nonzero magnitudes lie in [2^-256, 2^256] with max/min nonzero magnitude at most 2^32 (`N4M_DOMAIN_MAX_SPREAD_LOG2`) within each input array (exact zeros allowed; categorical codes are labels and are not checked). Holm and BH have no spread limit: p-values in [0, 1] whose nonzero values are normal (>= 2^-1022). Outside that domain Methods refuses before computing; the native and WASM providers map this refusal to `NUMERICAL_DOMAIN_EXCEEDED`, and both metrics of the affected metadata × target pair are `unsupported` with that reason. Every association metric publishes the domain in its `numerical_domain` parameter.

`association.metadata_target_test` carries a versioned `PermutationPlan` (`permutation_plan.v1`): null hypothesis, tested effect, statistic (`eta_squared`, `cramers_v_squared`, `eta_squared_of_metadata_by_target_class` or `abs_spearman_rho_two_sided`), exchangeable unit and whether exchangeability was declared, restrictions (`none_single_block`), block sizes, reduced model (none), draw method, Methods PCG64 RNG, decimal-string seed and its derivation, the log10 combinatorial bound on distinct arrangements, requested/executed counts, the Monte Carlo step `1/(B+1)`, the exact enumeration (`n_enumerated_arrangements`, `exact_minimum_p_value`) when the space has at most 100,000 distinct arrangements, the resulting `resolution` and its `resolution_basis` (`exact_enumeration`, or `lower_bound_from_combinatorial_bound` when the space is larger and `1/bound` is only a lower bound on the smallest exact p-value), p-value convention `(1+b)/(1+B)` and tie tolerance. The only executable plan is uniform unit-label permutation over one block. It requires a declared independence unit and `options.exchangeable_units = true`. In order, an unknown unit, a missing group, target or metadata varying inside a unit, a saturated design (one unit per level or per target class, `SATURATED_DESIGN`: the statistic cannot change under permutation), a target constant in the block and undeclared exchangeability return `not_identifiable` with their reason code. No restricted, crossed or residual permutation is substituted.

The family is every identifiable metadata × target test of the report (`association.metadata_target_family`), with Holm at 5 %. A test is executed only if its resolution is at most `0.05/m`; otherwise it is `insufficient_data` (`PERMUTATION_RESOLUTION_INSUFFICIENT`), carries no p-value, and enters Holm as p = 1. B = 999. Each test seed is `splitmix64_finalizer(options.seed XOR fnv1a64(domain))`, where the domain names provider, protocol, target and metadata. The root `options.seed` accepts a JSON number or a canonical decimal string (the WASM wrapper converts bigint and safe-integer inputs and refuses unsafe numbers), and all seeds are serialized as decimal strings so JavaScript hosts never round them. Executed permutations are recorded even when the Holm correction is unavailable; the test value then has `p_value_holm = null`, `rejects_null_at_family_alpha = null` and `multiplicity_available = false` with its reason, and no finding. Benjamini–Hochberg adjusted values of the same family are published as `p_value_bh_exploratory`, an exploratory secondary view (`exploratory_secondary` in the family metric, dependence assumption independence or PRDS, declared and not verified); they are never used for findings. A Holm rejection produces the exploratory finding `association.metadata_target.v1` with confidence `unknown`; it is not causal evidence.

The alpha integrity pass counts exact spectral pairs spanning declared physical samples after normalizing negative zero and honoring masks. It separately counts exact pairs across real development and retained-test observations under different physical IDs, with affected-observation denominators. This integrity check reads retained-test X only; it does not fit on test rows or inspect retained-test Y. Findings remain suspicions with unknown confidence. Exact matches never rewrite sample identity automatically.

Quasi-duplicates run only when `options.quasi_duplicates.tolerance` is declared (finite, positive, in the units of the chosen view); no default tolerance exists. Without it, `integrity.quasi_duplicate_pairs` and `integrity.cross_partition_quasi_duplicate_pairs` are `not_applicable` with `QUASI_DUPLICATE_TOLERANCE_NOT_DECLARED`, and the report's `quasi_duplicates` capability is unavailable with the same reason. The distance is the root-mean-square band difference in the declared view (`native` or SNV, reported as view `canonical:snv`) and context (`instrument_campaign`, the default; `instrument`, which pairs observations of one instrument across its campaigns; or `source`). Observations without a declared instrument or campaign share one context, which the metric states. Populations follow the exact pass: complete-case real development rows, pairs inside one physical sample excluded, and a separate development × retained-test comparison that reads retained-test X only. Each metric reports tolerance and unit, candidate and suspect pair counts, suspect-pair rate, affected-observation fractions and up to 1,000 listed pairs. Exact duplicates are included. Findings `identity.possible_quasi_duplicate_repeats.v1` (warning) and `identity.possible_cross_partition_quasi_duplicate.v1` (high) carry unknown confidence and never rewrite identities. Each listed pair carries descriptive `concordant_indices`: same instrument, campaign, `individual_id` and `independence_group` (true/false when both sides declare the key, null otherwise) and, for development pairs only, per target whether the exact eligible references are identical and share `reference_id` / `reference_group_id`. Development × retained-test pairs never compare references (`reference_comparison: not_performed_retained_test_Y_never_read`). The concordant indices are columns of the listed pairs only; they are not aggregated over unlisted pairs.

Spectral duplicates with incompatible references (`duplicate_reference_conflicts`, spec §5.5) are pure comparisons of declared values in Rust; no Methods kernel is involved beyond the pair search above. They run only for targets named in `options.reference_contradiction_tolerances`: `{"kind":"absolute","value":v}` (incompatible when |y_a − y_b| > v, target units) or `{"kind":"relative","value":v}` (incompatible when |y_a/m − y_b/m| > v with m = max(|y_a|, |y_b|), and compatible when m = 0; the normalized form cannot overflow, unlike v·m, so 1.7e308 against −1.7e308 at v = 1.5 is a conflict) for continuous targets, `{"kind":"different_class"}` for categorical ones. Values must be finite and positive; an unknown target or a kind that does not match the target is a blocking validation issue. Both continuous rules are decided exactly in rational arithmetic on the binary64 values: error-free TwoSum and fma products, with an exact sign of the resulting expansion. They are therefore exact for every finite value, including near-equal references such as `1e16` and `9999999999999998` at relative tolerance 2.1e-16. Only the published `absolute_difference` and `relative_difference` are rounded. Unit tests compare the decisions with an exact rational oracle (Python `fractions`) and check their invariance under power-of-two scaling (2⁻¹⁰⁷⁴ to 2¹⁰⁰⁰) and exact translations near 1e16 and 1e300. No tolerance is ever derived from data or lab precision. An undeclared target gives `not_applicable` with `REFERENCE_CONTRADICTION_TOLERANCE_NOT_DECLARED`. An absolute difference that cannot be represented exceeds every finite tolerance and is listed as null. Three metrics use the same rule:

- `reference.within_physical_sample_conflicts` (per target): pairs of sample IDs that declare the same `physical_sample_id`, i.e. aliases of one object. One object has one reference value, so no spectral evidence is required. This population is checked before, and separately from, the presumed repeats between objects, which the pair searches below exclude by physical identity.

- `reference.exact_duplicate_conflicts` (per source × target): the pairs of the exact pass (whole source, normalized float bits and mask sentinel, real development rows under different physical samples);
- `reference.quasi_duplicate_conflicts`: every development pair of `integrity.quasi_duplicate_pairs` in its view and context. Beyond the 1,000 listed pairs, Preflight asks Methods once more for the complete pair list of that context. It inherits the quasi-duplicate status and reason when that metric is unavailable, and its parameters name the spectral tolerance `spectral_tolerance` to keep it apart from the contradiction tolerance.

Pairs are reduced to unordered sample pairs: one comparison per sample pair, whatever the number of acquisitions. Only exact, internally consistent references of real development samples are compared (the population of `target.exact_eligible_samples`). Censored, composite, inconsistent and missing references are not compared and are counted in `n_sample_pairs_without_two_exact_references`. Retained-test Y is never read. A sample's admissible references are all its exact, consistent development references. They share one value, and their `reference_id` and `reference_group_id` values are kept as sets. `shared_reference_id` and `shared_reference_group_id` in the concordant indices are true when the two sets intersect, false when both are non-empty and disjoint, and null otherwise. This makes them independent of measurement order. Denominators separate `n_development_observations` (every real development observation of the source), `n_admissible_development_observations` (the population of the pair search: at least one valid cell for the exact pass, complete rows for the quasi pass) and `n_excluded_development_observations`. `fraction_denominators` names the denominator of each fraction. The value reports suspect, compared and incompatible sample pairs, the incompatible rate among compared pairs, affected samples (fraction of the development samples of the population that have an exact reference), affected development observations (those in an incompatible pair, fraction of the population rows), and up to 1,000 incompatible pairs with both references, reference IDs, the absolute difference and the smallest RMS difference. More than 1,000,000 retained development pairs gives `unsupported` with `SUSPECT_PAIR_BUDGET_EXCEEDED`; the X-side counts stay. A conflict produces the finding `reference.verify_reference_or_pairing.v1` (warning, confidence unknown): verify reference and pairing; nothing is removed.

`measurement.noise_proxy` (per band) and `measurement.noise_proxy_pooled` are computed per instrument × campaign on native real development acquisitions with equal weight. They are the root mean square of the Savitzky–Golay smoothing residual (default 11 bands, polyorder 2, configurable in `options.noise_proxy`) divided by the filter's white-noise residual gain. The window must be odd in [3, 1001] and the polyorder at most min(10, window − 2): Methods verified that domain to reproduce polynomial moments, and outside it the weights do not smooth as requested (window 41 / order 38 gave a residual of 0.83 on a constant row). The fields are u64 and validated without arithmetic that could wrap, so 32-bit WASM and 64-bit hosts reject the same inputs with `INVALID_NOISE_PROXY_PARAMETERS`. Only interior bands are evaluated; there is no padding at the edges. A window containing a masked cell is skipped. The axis must be uniform within 10⁻³ of its mean spacing (`NON_UNIFORM_AXIS` otherwise). Window, physical width, normalization, edge and mask behavior and the assumption (locally polynomial signal, white noise) are declared parameters. The label is `noise_proxy_not_snr`; no SNR is produced.

The Methods SNV, noise-proxy, tolerance-pair, nearest-neighbour and local-contrast kernels accept the supported numerical domain: every nonzero |x| in [2⁻²⁵⁶, 2²⁵⁶] and, per spectrum, max/min nonzero |x| ≤ 2³². The summary kernel applies only the magnitude bound, because its compensated moments and quartiles are correct for any spread (internal summaries such as ARI or per-level values are never refused for spread). A spectrum outside it is refused explicitly, never estimated. The dependent metric is `unsupported` with reason `NUMERICAL_DOMAIN_EXCEEDED`. On success and on refusal alike, each metric publishes the domain of its own operation in `numerical_domain`: spectra per row for SNV, the noise proxy and quasi-duplicates; magnitude only for value summaries (`target.continuous_distribution`); magnitude only for the neighbours (rounding-level PCA score components are accepted) and, for continuous targets, the global spread of the whole target vector for the local contrast (category codes exempt). The reference contradiction decisions are exact Rust comparisons and have no such limit.

`structure.snv_sensitivity` is on by default (`options.snv_sensitivity: false` disables it). SNV is applied to each acquisition of the canonical PCA population. The result is then aggregated with the same sample means and decomposed with the same number of components, as view `canonical:snv_centered`. The metric reports, for both views, eigenvalue shares of the full variance trace, the first-component and retained shares, the full-moment effective dimension, and the differences between the two views. `structure.snv_pca_eigenvalues` and `structure.snv_effective_dimension` give the SNV view itself. The comparison is descriptive and makes no attribution to nuisance or chemistry. Constant acquisitions map to exact zeros in the Methods SNV. The aggregation of technical repeats into one row per sample is also done in Methods: `n4m_preflight_snv_compute` with group IDs takes a compensated equal-weight mean. For each aggregated sample g it returns a first-order bound B_g on the rounding error of every entry. B_g covers the SNV of each acquisition, `(3uA + n²u² mean|y| + 2u²|m|)/sd_y + 8u max|z|` on power-of-two rescaled values with a double-double mean, plus the repeat mean, `(4u + 2 r u²) max|z|`. If the analytic SNV rows were identical, the per-band RMS deviation of the aggregated rows would stay below 2√2·max B, plus the PCA column-mean rounding n·u·max|z|. The residual variance therefore counts as resolved only if `sqrt(trace(C_snv)/p) > 4·(max_g B_g + n·u·max|z|)`, with trace(C_snv) the sum of the Methods per-band sample variances (`summary`, magnitude bound only). This is decided before the SNV-view PCA. Otherwise `structure.snv_effective_dimension` and `structure.snv_sensitivity` are `undefined` with `SNV_VARIANCE_NOT_NUMERICALLY_RESOLVED`, or with `ZERO_SNV_TOTAL_VARIANCE` when the residual is exactly zero, and the PCA is not run: rows that differ only by rounding residue (entries ~1e-17 next to ~1.4, outside the PCA domain) are never a domain refusal. If the PCA refuses a resolved SNV view, `structure.snv_sensitivity` is `unsupported` with `NUMERICAL_DOMAIN_EXCEEDED` and publishes the PCA domain ([2^-128, 2^128], spread <= 2^32). The SNV metrics publish `snv_total_variance`, `snv_rms_band_deviation`, `numerical_resolution_threshold`, `max_snv_entry_error_bound`, the criterion and `numerically_resolved`. The review examples give these values:

- rows `a·[1..5]+b`: RMS deviation 1.1e-15 for a threshold of 8.7e-15;
- the same offsets over 100,000 bands: 3.5e-19 for a threshold of 1.7e-12;
- `a·[1,2,4]` with 1/10000/1/1 rescans: exactly zero.

Repeatability uncertainty (`repeatability_uncertainty.v1`, PF-10, exploratory, unqualified) runs in every technical context (repeat type × instrument × campaign) that has at least two repeated physical groups. It uses the same rows, groups and band masks as `measurement.repeatability_sd`. Its rules are:

- Repeat counts: `measurement.repeat_counts` is published for every context. It gives the number of groups and of repeated groups, the repeated fraction, and min, max, mean, SD and type-7 quartiles of r_i (Methods summary), with a histogram. Counts are taken before band masks.
- REML: `measurement.icc_1_reml` is the REML ICC(1) of `x_ij = mu + u_i + e_ij` per band, for balanced or unbalanced designs. Every physical group with a valid band value enters, singletons included, so no sample is removed to fabricate balance. Methods rescales each band by exact powers of two chosen from its centred variation, profiles out s2_within, evaluates the profiled criterion and its derivative on a grid of gamma = s2_between/s2_within (step 1/8 decade), refines every local maximum and keeps the largest restricted likelihood, compared with the boundary s2_between = 0 (unbalanced designs can be multimodal). The metric carries s2_between, s2_within, the restricted log-likelihood, per-band counts, the number of candidates compared, bisection iterations and the numerical domain.
- Band status: each band has a status and a `band_reason`. 0 is an interior optimum. 1 is insufficient (`INSUFFICIENT_GROUPS_OR_REPEATS`). 2 is the boundary s2_between = 0, with ICC 0. 3 is zero total variance (`ZERO_TOTAL_VARIANCE`). 4 is the boundary s2_within = 0, with ICC 1. 5 is not converged (`REML_NOT_CONVERGED`). Boundary estimates are values, flagged and counted. A metric without any estimable band is `error` when a band failed to converge, `undefined` when every band has zero variance, and `insufficient_data` otherwise; a provider failure keeps its structured kind (unsupported, error).
- Chi-square interval: `measurement.repeatability_sd_ci_chi_square` is the exact 95 % chi-square interval of the within-group SD on the pooled within SS, with N−g df. It assumes normal homoscedastic within-group errors. It does not depend on independence between groups, so it is reported even when the independence unit is unknown.
- Exact F interval: `measurement.icc_1_1_ci_exact_f` is Searle's exact F interval of the balanced ANOVA ICC(1,1), not truncated, for bands where every group has the same r ≥ 2 after the mask. The F distribution assumes independent group effects, so a band is published only when every physical group present is its own independence component; otherwise its reason is `GROUPS_SHARE_INDEPENDENCE_UNIT` and the metric is `unsupported`. It requires a declared and resolvable independence unit.
- Cluster bootstrap: `measurement.repeatability_sd_ci_cluster_bootstrap` and `measurement.icc_1_reml_ci_cluster_bootstrap` are percentile (type-7) 95 % intervals, following the specification rule that intervals resample the declared independence unit. Each metric carries a `bootstrap_plan` (`bootstrap_plan.v2`). The percentile interval is not coverage-calibrated. Measured with the Methods kernel (1,000 simulations each, Monte Carlo SE 0.007, `parity/generators/variance_components_coverage.py` in Methods): ICC coverage 0.915–0.921 with 20 balanced pairs (0.973 at ICC 0), 0.898–0.915 with 24 unbalanced groups including singletons, 0.918–0.936 with 50–60 groups and 0.899 with dependent pairs resampled by unit; SD coverage 0.86–0.93, below the exact chi-square interval. BCa was rejected: 0.74 at ICC 0.1 with 20 groups (percentile 0.90 on the same draws), because its bias correction breaks on the boundary mass at ICC 0. Both intervals stay exploratory.
- Resampling units: the shared identity components of the engine (physical sample, individual, augmentation parent, declared `independence_group` when the unit is `group`, `reference_group_id` of every target), as for associations and confounding. The declared unit must resolve for every participating sample: `group` without `independence_group` gives `MISSING_INDEPENDENCE_GROUP`, `reference_group` without a `reference_group_id` gives `MISSING_REFERENCE_GROUP`, both `not_identifiable`; nothing falls back to physical samples.
- Draws: B = 999. The Methods PCG64 draws reproduce `numpy.random.default_rng(seed).integers(0, U, size=(B, U))`, and the same draws serve every band. The seed is `splitmix64_finalizer(options.seed XOR fnv1a64(domain))`, where the domain names the protocol, the source and the context; it travels as a decimal string.
- Bootstrap gates: an unknown unit gives `not_identifiable`. Units are counted per band after the masks (`n_units_with_valid_value_per_band`, `n_units_with_within_df_per_band`); a band needs 20 units with a valid value for the ICC and 20 units carrying within-group df for the SD (`FEWER_THAN_20_RESAMPLING_UNITS`, `FEWER_THAN_20_UNITS_WITH_WITHIN_DF`), and all 999 replicates estimable (`BOOTSTRAP_REPLICATES_NOT_ESTIMABLE`). No band with 20 units, or work above `B × bands × (groups + 1024) = 2.5e9` (`BOOTSTRAP_WORK_BUDGET_EXCEEDED`), skips the bootstrap.
- Numerical domain (lead rules 13 and 15): Methods accepts every nonzero |x| in [2^-256, 2^256] with max/min nonzero |x| <= 2^32 (`N4M_DOMAIN_MAX_SPREAD_LOG2`) over the values of each band, and the same bound on their pairwise differences, measured as (max − min) over the smallest nonzero gap between sorted values. Outside it the call is refused before computing; the five metrics are then `unsupported` with `NUMERICAL_DOMAIN_EXCEEDED` and publish `numerical_domain`, as the computed metrics do. Inside it, results are scale and translation invariant and within sums of squares keep full relative precision. The balanced-repeat sensitivity applies the magnitude and spread bounds per band to the acquisitions it averages.
- REML grid limitation: with K distinct group sizes the derivative of the profiled criterion has the sign of a polynomial of degree <= 4K-3, so balanced designs (K = 1) are unimodal and always solved. For K >= 2, a whole local maximum lying inside one grid cell (a factor 10^(1/8) = 1.334 in gamma) is not seen; its spacing is not bounded, so the published estimate is the best of the maxima the grid resolves, and `reml_candidates_per_band` counts them.

`structure.balanced_repeat_sensitivity` (`balanced_repeat_sensitivity.v1`) compares the canonical structure with a declared balanced-count variant. Each aggregated sample keeps r* = min r_i of its acquisitions, drawn without replacement by SplitMix64 partial Fisher–Yates with a derived seed. Samples with one acquisition stay. The same mean, centering and number of PCA components are then applied. The metric reports eigenvalue shares, retained share and effective dimension for both views and their differences, with r*, the r_i histogram, the seed and its derivation. One subsample is drawn. Equal counts give `not_applicable` (`REPEAT_COUNTS_ALREADY_EQUAL`). The comparison is descriptive. Each balanced mean comes from a Neumaier compensated sum (lost addition errors are accumulated and added back, so [2^60, 1, −2^60] averages to 1/3 in every order), then one division; tests compare every permutation with a rational oracle.

The JSON input and report schemas are version 1. Internal Methods adapter contracts are Rust structs in `nirs4all-preflight-core/src/lib.rs`; host adapters must validate native shapes, finite numbers, and ABI versions before returning values. C API, WASM and language bindings must call this same engine, never duplicate the protocol.

PCA reports scores with actual representative declared sample IDs and separate aggregation keys inline up to 100,000 score cells, full variance moments, and retained explained-variance fraction. The inline limit is an explicit alpha report budget; a future asset transport is needed for larger score tables. A zero-rank source has undefined PCA geometry and local contrast. Input and report carry an optional `data_origin` label, including `synthetic` for demonstrations. The HTML export prints audit context and summarizes large arrays; JSON remains the complete scientific record.

Clustering (PF-05, protocol `clustering.v3`, exploratory, unqualified) uses the same eligible aggregated samples and canonical PCA scores as `structure.*`, in their canonical BTreeMap order. HDBSCAN results depend on row order and tie order, so that order is part of the protocol. The policy is frozen as follows:

- Parameters: `min_cluster_size = min_samples = max(5, ceil(n/20))`, where `min_samples` includes the sample itself, with EOM selection and `allow_single_cluster = false`. Fewer than `2 × min_cluster_size` eligible samples gives `FEWER_THAN_TWO_MIN_CLUSTER_SIZES` for every clustering metric.
- Score grid: every score matrix passed to HDBSCAN (full, subsample and null) is rounded half away from zero to multiples of `2^(e−24)`, where `max|score|` lies in `[2^(e−1), 2^e)`. Power-of-two steps make the rounding exact on every host. Without it, last-ulp PCA differences between native and WASM (4.4e-16 on the review case) changed near-tied mutual-reachability orders and gave 7 versus 8 groups. Residual risk, pinned by a unit test: a score one ulp below a grid midpoint rounds down while the midpoint and one ulp above round up, so a one-ulp host difference there moves the score by one grid step; likewise a `max|score|` one ulp either side of a power of two changes the step by a factor of two. With host differences of the order of 4e-16 relative, a given score lies that close to a midpoint with probability of the order of 1e-8. Cross-host parity is therefore pinned by goldens and explicitly not guaranteed for such values; the partition parameters say so (`cross_host_parity`). Reported tree distances are in grid-rounded score units.
- Resampling units: rows are merged by shared `individual_id` and, according to `independence_unit`, by `independence_group` (`group`; missing gives `MISSING_INDEPENDENCE_GROUP`) or by the reference group (`reference_group`). A row's reference group is the single `reference_group_id` carried by its references over all targets, whatever their status; no group gives `MISSING_REFERENCE_GROUP` and several give `AMBIGUOUS_REFERENCE_GROUP`, both `not_identifiable`. Y values are never read. `sample` keeps one unit per physical sample. `unknown` resamples rows as a descriptive sensitivity only, reported as `resampling_unit = eligible_sample_undeclared_independence` and `independent_unit_resampling = false`; it can never yield a stable-partition assessment. Fewer than five units gives `FEWER_THAN_FIVE_RESAMPLING_UNITS`. Units are ordered by their first eligible row.
- Plans: one Methods PCG64 stream, `n4m_random_permutations`, equal to `numpy.random.default_rng(seed).permutation(U)` drawn 50 times. Subsample `b` keeps the units `sorted(permutation_b[0:ceil(0.8 U)])`. The seed is `splitmix64_finalizer(root_seed XOR fnv1a64("nirs4all-preflight\0methods\0clustering.v3\0subsample_plans\0" + source_id))` and travels as a decimal string. The same 50 plans serve both parameter variants and the null model; the unit plans and each unit's first row are published in `clustering.subsample_stability`.
- Refit: each subsample repeats centering, PCA (`min(10, m−2, p)` components), the score grid and HDBSCAN on the aggregated spectra, once with `ceil(0.8 × parameter)` (floors 2 and 1) and once with the constant full-sample parameters (`clustering.subsample_stability_constant_parameters`).
- Comparison: every drawn identity is common to both partitions. Each subsample reports the intersection size, the size of the identities assigned to a cluster in both partitions, its ARI (only with at least 10 such identities and two clusters in both partitions on them), cluster count, noise fraction and assigned/noise agreement. Summaries separate the intersection fraction of eligible samples from the assigned-in-both fraction, and give the ARI population size and its fractions of eligible samples and of the intersection over exactly the ARI-evaluable subsamples.
- Budget: `50 × n² × (p + 20) > 2.5e10` gives `STABILITY_WORK_BUDGET_EXCEEDED`.

Cluster appearance frequency (`cluster_matching.v1`, one metric per parameter variant): in each subsample, each reference cluster restricted to the drawn identities is compared with each subsample cluster by Jaccard (Methods `n4m_cluster_jaccard_matrix`; noise is in no cluster). A one-to-one assignment maximizing total Jaccard is computed by Methods `n4m_linear_sum_assignment`, the SciPy 1.18.1 `linear_sum_assignment` port with its tie order, with reference labels as rows and subsample labels as columns in ascending order. An unmatched reference cluster has Jaccard 0. A cluster appears when its matched Jaccard is above 0.5; a subsample is evaluable for a cluster when at least one of its members was drawn. Each cluster reports evaluable and appearance counts, the appearance frequency, and summaries of the matched Jaccard and of the drawn member fraction. Without reference clusters the metric is `not_applicable` (`NO_REFERENCE_CLUSTERS`).

Gaussian null model (`clustering.gaussian_null_model`): a unimodal Gaussian with zero mean and covariance `diag(λ) + 1e-6 × mean(λ) × I`, where `λ` are the Methods PCA eigenvalues (ddof 1) of the canonical scores, which are centered and uncorrelated. Each of B = 99 replicates draws `n` independent rows with Methods `n4m_random_multivariate_normal` (NumPy `multivariate_normal(..., method="cholesky")` on PCG64) from a seed derived per replicate (`...\0gaussian_null\0` + source_id + `\0` + b).

- Same protocol on both sides, frozen projection: the observed canonical scores and each replicate's simulated scores are subsampled with the same 50 plans without any PCA refit, rounded to the score grid and clustered with the scaled parameters; full partitions use the full-sample parameters. The refit stability metrics stay reported but are not compared with the null, because the observed refits start from `p` bands while the null only has the `d` retained components.
- Pre-specified statistic: the coverage-weighted stability, the median over the 50 subsamples of `ARI × (assigned in both / drawn)`, with 0 when ARI is not evaluable. Its exploratory fitted-null tail fraction is `(1 + #{T_b ≥ T_obs})/(1 + B)`, ties counting against the observation, resolution 0.01 (`fitted_null_tail`). It is **not** an exact Monte Carlo test: the Gaussian (PCA eigenvalues, retained dimension) is estimated from the same data, so the observed and simulated statistics are not exchangeable and no type-I error level is guaranteed. Even a valid test would only concern an excess of this stability over this one fitted model. The qualification path, declared in the parameters, is a parametric bootstrap that re-estimates the PCA and the Gaussian in every simulated dataset, with the level of the resulting rule checked by simulation.
- Decisional scope: simulated rows are independent, so the test decides only when every resampling unit is one row with a declared independence unit. With multi-row units (`MULTI_ROW_RESAMPLING_UNITS`), undeclared units (`INDEPENDENCE_UNIT_UNDECLARED`), no plans or the null stability over budget, it is descriptive only. A grouped null (simulated unit centres plus within-unit deviations) was not chosen: the within-unit structure of aggregated spectra in a lot or group is not known to be Gaussian, and simulating it would add an unvalidated model to the decision.
- Descriptive only: per-replicate cluster counts, noise fractions, statistics and median ARIs, marginal tails `(1 + #null ≥ observed)/(1 + B)` and `(1 + #null ≤ observed)/(1 + B)`, and the number of replicates dominating on cluster count, noise and statistic. A joint dominance tail is not a 5 % tail and no longer drives any verdict.
- Budget: the null is `unsupported` when `99 × n² × (d + 20)` exceeds 2.5e10, and its stability part (hence the test) is skipped when `99 × 51 × n² × (d + 20)` does. The parameters state that the model is one unimodal Gaussian and does not represent curved or branched manifolds, gradients, heavy tails or heteroscedastic continua.

Assessment (`clustering.partition_assessment`, rule `clustering_assessment.v3`, thresholds declared and not validated) publishes each criterion with its value, threshold and outcome: fewer than two groups gives `no_density_separated_groups`; a decisional fitted-null tail fraction above 0.05 gives `compatible_with_fitted_gaussian`; otherwise `stable_candidate_versus_fitted_gaussian` requires declared independent units, median refit ARI ≥ 0.8 under both parameter variants, every scaled appearance frequency ≥ 0.8, a median assigned-in-both fraction of eligible samples ≥ 0.5, a decisional null and a tail fraction ≤ 0.05; anything else is `uncertain_partition`. Verdict names and findings (`structure.clustering.continuous_structure.v3`, `structure.clustering.stable_candidate_partition.v2`, `structure.clustering.uncertain_partition.v3`) say that the comparison is with a Gaussian fitted to the same data and carries no type-I error guarantee; all have confidence `unknown` and never state a firm number of clusters. Native, canonical and supervised structures are not compared: only the canonical view is clustered, and this alpha has no supervised latent space.

The full chain is pinned by `crates/nirs4all-preflight/tests/fixtures/clustering_v3_golden.json`, written by `scripts/generate_clustering_golden.py`: an independent NumPy 2.4.6 / SciPy 1.18.1 / scikit-learn 1.9.1 implementation of the protocol with the Methods stable MST tie order. Seven datasets cover the first review's tie-heavy case with undeclared units, another tie-heavy case, separated blobs, a Gaussian continuum with single-row reference groups, the second review's 12 unit centres × 5 near-identical rows declared as groups, 20 bands of similar variance (no groups) and three blobs in 15 bands. The native and WASM engines reproduce the partitions up to label permutation, the 50 PCG64 unit plans, every subsample comparison, the appearance counts, the 99 null replicates, the observed statistic, the fitted-null tail fraction, the decisional flag and the assessments; real values agree within 1e-12. The grouped case is `uncertain_partition` with a non-decisional null, where the previous rule accepted it as stable.

Numerical domain (rules 13/15): the Methods clustering kernels accept finite inputs with every nonzero `|x|` in `[2^-256, 2^256]` and max/min nonzero `|x|` `≤ 2^32` (Methods macros `N4M_DOMAIN_MAX_MAGNITUDE_LOG2`, `N4M_DOMAIN_MAX_SPREAD_LOG2`), and refuse anything else before computing. The native adapter and the WASM bridge turn that refusal into the reason `NUMERICAL_DOMAIN_EXCEEDED` (metric status `unsupported`), and every clustering metric publishes the domain in `numerical_domain`. Because HDBSCAN receives grid-rounded scores, whose nonzero values span at most `2^24` below the largest, only magnitudes beyond `2^±256` can reach the refusal; at those scales the upstream PCA fails first today.

Robustness: the score grid is exactly scale-equivariant (scaling by `2^k` scales the rounded scores by `2^k` while the step is normal; unit test over `k ∈ {−1014, …, 1000}`), the null ridge uses an overflow-free mean of the eigenvalues, and every Methods kernel used here (HDBSCAN, Jaccard, assignment, ARI, Gaussian draws) states its domain of validity and either keeps its scale invariances or returns an explicit error. The engine-level sweep (`native_clustering_magnitude_sweep`) scales the blob golden by `2^k`: the partition is unchanged for `k = ±100`, and for `|k| ≥ 500`, `k ≤ −1014` and a constant `1e300` band the upstream Methods PCA reports an error or `ZERO_NUMERICAL_RANK`, so clustering stays unavailable with that reason. The tiny-scale `ZERO_NUMERICAL_RANK` is a PCA moment underflow outside this module and is reported upstream.

Confounding (`confounding.v1`, PF-06 first half, exploratory, unqualified) uses the same eligible aggregated samples and canonical PCA scores as `structure.*` and clustering. Its rows are independence units: the identity components of `independence_components` (every declared sample; physical sample, individual, augmentation parent, `independence_group` for unit `group`, and the reference groups of every target), built before any exclusion and then projected onto the eligible rows, so samples absent from the source, masked out of the structure or augmented still link the rows they connect. A unit's coordinate is the equal-weight running mean of its rows' scores (no sum that could overflow); with unit `sample` and no links the coordinates are the scores themselves. Distances are Euclidean. Factors are the categorical metadata of `QualificationInput::metadata_factors()` (`instrument`, `campaign`, then categorical columns of the typed metadata map), read with `metadata_value()`. One population is shared by every factor so that sums of squares are comparable: units with a missing factor are excluded and counted, and units whose factor varies internally are excluded, counted and make every test of the source `not_identifiable` (`METADATA_VARIES_WITHIN_INDEPENDENCE_UNIT`). With unit `reference_group`, a participating unit whose component carries no reference group makes every test `not_identifiable` (`REFERENCE_GROUP_UNRESOLVED`, denominator `n_units_without_reference_group`); no sample-level plan is substituted. Fewer than three units gives `FEWER_THAN_THREE_INDEPENDENCE_UNITS`; no declared factor gives `NO_DECLARED_FACTOR`; a single-level factor gives `SINGLE_FACTOR_LEVEL`.

- `confounding.design` lists factor levels with unit counts, pairwise crossing tables, and per factor the nominal df, the identifiable df given the cells of the other varying factors (levels minus the connected components of the level × other-cell occupancy graph, from Methods), the design rank with those cells, `aliased_with_other_factor_cells` (identifiable df 0 relative to the cells of the other factors, interactions included), `identifiable_under_additive_model` (Freedman–Lane df > 0 given the other main effects), `partially_confounded` and `determined_by` (other factors each of whose levels holds a single level of this factor). Additive identifiability has three states. Identifiable (A = B xor C): finding `confounding.aliased_with_other_cells.v1` (info, separation only if interactions are absent). Not identifiable: `confounding.aliased_factors.v1` (warning, neither design separates the factor). Unknown, when the Freedman–Lane computation is unavailable or over budget: `identifiable_under_additive_model` is null, `additive_identifiability_reason_code` keeps the reason, and the finding `confounding.aliased_with_other_cells.v1` (warning) reports only the cell aliasing and that the additive question is open.
- `confounding.variance_partition` reports the total SS, per factor the marginal R² (factor alone), the unique R² given the other factors' cells (`SS(cells + factor) − SS(cells)`, the vegan `adonis2(by = "margin")` SS when there is one other factor), partial R², pseudo-F and df, and the R² of all factor-level combinations. `shares_are_not_additive` is always true; no share is presented as exclusive.
- `confounding.dispersion` is PERMDISP per factor (vegan `betadisper(type = "centroid")`): mean distance to each level centroid and the ANOVA F. It is a diagnostic only and never validates exchangeability or a PERMANOVA.
- Tests carry a `permutation_plan.v1`: `confounding.permanova_marginal_test` (free permutation of units, `none_single_block`), `confounding.permanova_conditional_test` (units permuted only inside the cells of the other varying factors, `within_blocks`, block sizes listed; blocks never move) and `confounding.permdisp_test` (permutation of the ANOVA residuals of the distances, as vegan `permutest`). The statistic is the pseudo-F (PERMANOVA, `permanova_pseudo_f` or `permanova_pseudo_f_given_strata`) or the ANOVA F of the distances (PERMDISP, `permdisp_anova_f`); as vegan, a draw counts when `F_perm >= F_obs − sqrt(DBL_EPSILON)` (`tie_tolerance`), never on a monotone transform of F. A conditional test with identifiable df 0 is `not_identifiable` (`FACTOR_ALIASED_WITH_OTHER_FACTORS`); with no other varying factor it is `not_applicable` (`NO_OTHER_VARYING_FACTOR`). An undefined statistic is `undefined` (`PSEUDO_F_UNDEFINED`, `DISPERSION_F_UNDEFINED`; a zero total SS makes the partition `ZERO_TOTAL_VARIANCE`). As for associations, an unknown unit, a missing group or undeclared `exchangeable_units` makes every test `not_identifiable`. The conditional test tests "no effect of the factor in any cell of the other factors" (maintainer decision; the Freedman–Lane test below complements it); strata where the factor is constant contribute no admissible permutation. Tests concern fixed effects of the observed levels and say nothing about new instruments or campaigns.
- `confounding.permanova_freedman_lane_test` is a second, separate conditional test of each factor: the main effect given the additive main effects of the other varying factors (intercept + other main effects, no interaction, `reduced_model` filled in the plan), by Freedman–Lane permutation of the reduced-model residuals over all units (`none_single_block`, statistic `permanova_pseudo_f_given_main_effects`, Methods `n4m_stats_permanova_freedman_lane`). It is approximate (exchangeable residuals) but its null admits interactions with the other factors, whereas the within-cells test is exact under the stricter null "no effect in any cell". A separate metric, not a mode of `confounding.permanova_conditional_test`, keeps one null hypothesis and one plan per metric and lets both enter the Holm family as distinct hypotheses. A saturated reduced model gives `not_identifiable` `REDUCED_MODEL_SATURATED`, an aliased factor `FACTOR_ALIASED_WITH_OTHER_FACTORS`, and a design without residual df `SATURATED_DESIGN` (also applied to the marginal and within-cells tests). The variance partition adds `*_given_other_main_effects` values and the design `df_identifiable_given_other_main_effects`. A Holm rejection gives the finding `confounding.main_effect_structure.v1`.
- Families: `confounding.permanova_family` (marginal, within-cells and Freedman–Lane tests of one source) and `confounding.permdisp_family`, each with Holm at 5 %, a resolution guard `max(1/(B+1), 10^−log10 distinct) <= 0.05/m` (`resolution_basis = lower_bound_from_combinatorial_bound`: no exact enumeration exists for these statistics, so the bound only bounds the smallest attainable p from below), otherwise `PERMUTATION_RESOLUTION_INSUFFICIENT` and p = 1 in Holm, and B = 999. Seeds are `derive_seed(options.seed, "nirs4all-preflight\0methods\0confounding.v1\0{source}\0{test}\0{factor}")`, the derivation shared with associations (`nirs4all_preflight_core::derive_seed`), sent as decimal strings.
- Findings, all with confidence `unknown`: `confounding.aliased_factors.v1` (warning, separate effects not identifiable; complete the crossings and check Y coverage of each crossing and the metadata–Y associations), `confounding.marginal_structure.v1` and `confounding.conditional_structure.v1` (warning, Holm rejection; compare with the metadata–Y association and hold out the factor's levels if the intended use includes new levels; never causal) and `confounding.dispersion_heterogeneity.v1` (info). When metadata associations are reported, their metric is cited as evidence.

On `examples/confounding.json` (instrument × campaign, 2026 holding instrument b only), an independent NumPy 2.2.6 reproduction on the reported scores (`lstsq` on full one-hot designs, `default_rng` draws) matched every R² within 1e-15 and every permutation count, natively and in WASM. Not delivered: nested or random domain factors, interaction tests, cluster explanations and prediction of metadata from X.

Provider failures are structured (`ProviderError { kind, reason, detail? }`, one mapping of Methods failures `ProviderError::from_methods_error(status, message)`) and shared by every capability. `unsupported` is reserved for an absent capability or a declared limit (library or ABI missing, work and memory budgets, Methods `UNSUPPORTED`/`NOT_IMPLEMENTED`/ABI/version/backend statuses) and gives the metric status `unsupported`; numerical failures (Methods `NUMERICAL_FAILURE`, `CONVERGENCE_FAILED`) and internal failures (invalid requests, memory, callback transport) give `error`. The reason is a stable code, `METHODS_<STATUS>` for Methods statuses: the native adapter maps the C status, and the WASM adapter forwards the Methods exception status for the Rust engine to map with the same function, so CPU and WASM report the same kind and reason.

Every confounding metric carries a structured `numerical_domain` parameter (same keys as the association metrics). The Methods PERMANOVA, Freedman–Lane and PERMDISP kernels accept the shared supported domain D (rules 13 and 15): a finite unit-coordinate matrix whose nonzero magnitudes lie in [2^-256, 2^256] with max/min nonzero magnitude at most 2^32 over the whole matrix (`N4M_DOMAIN_MAX_SPREAD_LOG2 = 32`, exact zeros allowed). Outside D Methods refuses before computing; `ProviderError::from_methods_error` (shared by the native adapter, which reads `n4m_context_last_error`, and the WASM bridge, which forwards the `N4mError` status and message) maps the refusal to `unsupported` with reason `NUMERICAL_DOMAIN_EXCEEDED`, and the affected metric publishes no value. Inside D the kernels centre each column before choosing a power-of-two scale from the centred variation (constant columns and offsets have no effect, the rescaling is exact; centring rounds each value by about n·ε times its coordinate's range), compute every residual sum of squares from explicit residuals (observation and each permutation), form F in the scaled unit, and publish sums of squares and distances as `value × 2^binary_exponent` (`ss_binary_exponent` in the variance partition, `distance_binary_exponent` in the dispersion metric; 0 when every positive value is a normal double). An F is undefined only when its residual SS is exactly zero; otherwise it is published with its resolution object (`numerically_unresolved`, `residual_ss_resolution_ratio` = Methods error estimate of the residual SS divided by it, a conservative first-order estimate rather than a proof; unresolved when the ratio is ≥ 1) in `pseudo_f_*_resolution`, `anova_f_resolution` and each test's `statistic_resolution`. The Freedman–Lane partial R² is SS_term / (SS_term + SS_residual) of one projection of the twice-projected reduced-model residuals. Engine tests (native and WASM) check identical R², pseudo-F and permutation counts for spectra scaled by 2^k inside D and `NUMERICAL_DOMAIN_EXCEEDED` when the unit coordinates fall below 2^-256 (spectra at 2^-258, 2^-262); the provider-level tests cover the dyadic fixture at the 2^32 spread boundary with 16, 24 and 32 rows (F = 13, 21, 29, partial R² 0.5), its 2^33 and 2^64 variants (refused), a 2^31 offset stratum (SS_A = 2, SS_res = 3, F = 10/3; 2^60 refused) and the resolution flag (one-ulp residuals: finite F flagged unresolved; zero residual SS: F undefined). The canonical PCA (`n4m_preflight_pca_compute_resolved`) declares its own domain, nonzero |x| in [2^-128, 2^128] with spread <= 2^32: outside it the structure and confounding metrics are `unsupported` with `NUMERICAL_DOMAIN_EXCEEDED` (±1.7e308 spectra, formerly a numerical failure, on both hosts), so the engine scale sweeps run at 2^±100 and 2^±120.

Domain shift (`domain_shift.v2`, PF-06, exploratory, unqualified) compares domains of each source in the canonical view (native signal, centred; no scaling). It runs after the metadata associations, whose results it reads for its recommendations.

- Estimand: every comparison and test is between distributions of independence-unit mean spectra (`estimand = distribution_of_independence_unit_mean_spectra`). Development and retained-test rows are aggregated as for `structure.*`, merged into units by `independence_components` (physical sample, individual, augmentation parent, `independence_group` when the unit is `group`, every target's `reference_group_id`), and each unit is the equal-weight mean of its aggregated samples. Every comparison and test publishes its composition (units, aggregated samples, minimum and maximum samples per unit on each side). When units hold different numbers of samples, their means do not share one dispersion even under exchangeable samples, so the test is `not_identifiable` (`UNEQUAL_UNIT_COMPOSITION`); no balanced sensitivity is implemented.
- Domains: each declared categorical factor (`instrument`, `campaign`, and categorical metadata columns) with at least two levels among units whose samples share one level. Each level is compared with the others (`level_vs_rest`). Under `options.domain_shift.external_domain_audit`, development is also compared with retained-test X (`development_vs_retained_test`). Before the split by partition the audit checks whole identity components and declared groups: any component or group holding both development and retained-test samples makes every audit metric `not_identifiable` (`AUDIT_UNITS_SPAN_PARTITIONS`, with up to 20 `crossing_sample_ids`; input validation already blocks these inputs). Retained-test Y is never parsed or read; the report is invariant to it.
- Per comparison (at least three reference units, else `FEWER_THAN_THREE_REFERENCE_UNITS`): `domain_shift.distribution_distance` (`energy_e` = 2E|X−Y| − E|X−X'| − E|Y−Y'| in the signal unit with its absolute rounding bound and interval, `scipy_energy_distance` = its square root, mean distances) on complete spectra, which no learned subspace or bandwidth affects; `domain_shift.center_shift` (centroid distance, its parts inside and outside the reference PCA subspace, centroid T²); `domain_shift.dispersion` (covariance traces of unit means, ddof 1, ratio; `ZERO_REFERENCE_VARIANCE` or `FEWER_THAN_TWO_TARGET_UNITS`); `domain_shift.coverage`. The reference PCA asks for k = min(10, n_ref − ceil(n_ref/K) − 1, p) components with K = min(10, n_ref) folds; in each fit separately (every out-of-fold fit and the full fit), a component is resolved when its eigenvalue exceeds that fit's resolution 16·m·ε·λ₁ (m = max(fit rows, bands), λ₁ the fit's largest eigenvalue); components at or below it are unresolved and discarded, and the effective k (`n_components_effective`, with the full fit's `eigenvalue_resolution`) is the smallest number of leading resolved components over all fits. `component_rule` publishes this criterion. Limits are the empirical type-7 0.95 quantiles of out-of-fold reference T² and Q (unit at position i in fold i mod K). Q is the squared norm of the explicit residual. Coverage counts are not certified decisions: with the conservative tolerance τ = 16·m·ε·λ₁/λ_k (an estimate, not a proven bound; `tolerance`, `reference_condition`), a target unit is counted beyond a limit when it exceeds it by more than τ·max(T², limit) for T² or τ·S_i for Q, with S_i = max(‖x_c,i‖², max_j ‖x_c,j‖²) over the out-of-fold centred reference units j and the target unit i; `q_tolerance_max` = τ·max_i S_i is only the largest of these per-unit tolerances, so a unit can be counted beyond with a Q below it, and as near the limit (`n_target_near_*`, numerically undetermined) when it lies strictly inside that band. With no resolved component, T² values and the combined count are `null` with `REFERENCE_NUMERICAL_RANK_ZERO` and `T2_UNAVAILABLE_COMBINED_COVERAGE_INCOMPLETE`; Q stays available. `domain_shift.target_change` summarizes exact development Y per unit in both domains.
- Units: every object value lists `value_units` (signal, its square or root, the target unit, or dimensionless); `metric.unit` is left empty for mixed objects.
- Tests: one K-sample energy test per factor (statistic Σ_{a<b} n_a n_b/(n_a+n_b) E_ab, R `energy::eqdist.etest`) on unit-mean complete spectra, with a `PermutationPlan`: uniform unit-label permutation in one block, B = 999, Methods PCG64 draws, seed `derive_seed(options.seed, "nirs4all-preflight\0methods\0domain_shift.v1\0<source>\0<factor>")`, declared tie rule `T_perm − T ≥ −sqrt(eps)·|T|` (the plan's `tie_tolerance`, exactly what Methods counts); draws within twice the rounding estimate of T of that threshold are published as `n_undecidable_draws`, with `p_value_conservative` counting them as ties, while Holm uses `p_value`. Unknown unit, missing group, undeclared exchangeability, a factor varying inside a unit or unequal unit composition give `not_identifiable`; the comparisons stay descriptive. The development factors of a source form one Holm family at 5 % (`domain_shift.test_family`); a test whose resolution `max(1/(B+1), 1/distinct)` exceeds `0.05/m` is `insufficient_data` (`PERMUTATION_RESOLUTION_INSUFFICIENT`) and enters Holm as p = 1. The audit test is its own family of one.
- Findings (confidence `unknown`): `domain_shift.detected.v1` (warning), whose action follows `options.domain_shift.intended_use` (`new_levels`: hold whole levels out; `seen_levels`: keep every level represented; undeclared: ask for the declaration), adds the Y caveat when `association.metadata_target_test` rejects for the same factor and the aliasing caveat; `domain_shift.aliased_domains.v1` (info); `domain_shift.external_domain_audit.v1` (info, no recommendation is derived from the audit).
- Numerical domain (lead rule 15): unit-mean spectra must have finite values, every nonzero |x| in [2^-256, 2^256] and a spread of at most 2^32 (Methods `N4M_DOMAIN_MAX_SPREAD_LOG2 = 32`) (`numerical_domain` on every metric). Outside it Methods refuses before computing and the metrics are `unsupported` with `NUMERICAL_DOMAIN_EXCEEDED` (native and WASM adapters map the Methods context message). Inside it energies come from local pairwise differences with double-double sums and combination (symmetric, with conservative rounding estimates, not certified bounds); the monitor centres each set on its own double-double mean, so a 2^60 reference level does not erase the targets' own differences. Preflight rejects any provider result with a negative or non-finite energy, inconsistent counts or ranks (`INVALID_PROVIDER_RESULT`), so no `computed` metric carries NaN or a value-less success. The CPU and WASM adapters check the Methods budgets (pairs, cells, group table, operations) before allocating. A magnitude sweep (2^k, k from −1062 to 1000) gives identical counts, p-values, limits and effective k inside the domain and `NUMERICAL_DOMAIN_EXCEEDED` outside it. An audit with no development unit is `insufficient_data` (`NO_DEVELOPMENT_UNITS`).

Validation probe (`validation_probe.v1`, PF-04, exploratory, unqualified). It runs once per source × continuous target × fixed recipe:

- `pls`: Methods `models.pls.pls_regression`, NIPALS.
- `pcr`: Methods `models.pls.pcr`.

Both recipes center X and Y inside each fit and do not scale. `options.validation_probe` sets `enabled` (default true), `estimators` (default both) and `max_fits` (default 500).

- Population. The probe uses real development samples with exact, internally consistent references; retained-test, prediction and augmented rows are never read. Technical repeats within one physical sample × instrument × campaign are averaged by Methods `n4m_stats_group_means` before any fit, giving one OOF prediction per sample. Multi-context physical samples, ambiguous or non-technical repeats, unreferenced samples and incomplete rows are excluded and counted. Domains are structured `(instrument, campaign)` pairs; an absent value stays `null` and never merges with another domain.
- Components. They come from the shared `independence_components` (`IdentityKey`), built over every sample before any exclusion. They link physical sample, individual, augmentation parent, reference group of the target and, for `independence_unit = group`, the declared group. A component never crosses a fold. Cross-partition links are refused earlier by input validation, so no FIT runs. With `independence_unit = reference_group`, every retained component must carry a resolved reference group of the target, possibly through another sample of the component, even an excluded one. Otherwise the probe is `not_identifiable` (`REFERENCE_GROUP_UNRESOLVED`) before any fit.
- Refusals before any fit:
  - `INDEPENDENCE_UNIT_UNKNOWN`, `MISSING_INDEPENDENCE_GROUP`;
  - `EXACT_DUPLICATE_SPECTRUM_ACROSS_COMPONENTS`, `CONSTANT_TARGET`;
  - `FEWER_THAN_THREE_INDEPENDENT_GROUPS`, `TOO_FEW_SAMPLES_FOR_COMPONENT_GRID`, `ZERO_NUMERICAL_RANK`;
  - `FIT_BUDGET_EXCEEDED`, `NUMERICAL_DOMAIN_EXCEEDED`;
  - `PROBE_METHODS_KERNELS_NOT_CONFIGURED`.

  Categorical targets give `CLASSIFICATION_PROBE_NOT_QUALIFIED`; no Methods classifier is qualified on every host.
- Plan. With G components, the probe uses `min(5, G)` outer folds and `min(3, outer − 1)` inner folds. Grouped K-fold assigns the largest group to the lightest fold, so every fold holds at least one group and at most `n/k + s_max` rows. The smallest inner training pool is therefore at least `B = (n(1 − 1/outer) − s_max)(1 − 1/inner) − s_max`. The grid is `1..=min(10, p, r, ⌊B⌋ − 1)`, where `r` is the numerical rank of the centered aggregated matrix: Methods PCA eigenvalues with the NumPy `matrix_rank` rule `s_i > s_1 max(n, p) ε`. PLS and PCR beyond the rank are ill-posed. The plan expects exactly `outer × (grid × inner + 1)` fits.
- DAG-ML. `execute_nested_selection_with_metrics` owns every loop, the comparison of candidates and the tie rule. The metrics that decide the selection (pooled inner-OOF RMSE) and summarize the outer OOF come from Methods `n4m_stats_regression_scores`: a native metrics provider on CPU, a JS callback in the browser. It builds all fold sets before any fit, runs FIT_CV of each candidate on the inner folds, selects by minimum pooled inner-OOF RMSE (`select_candidate`, ties to fewer components), then runs FIT_CV of the winner on each outer training pool, which predicts only its validation rows. Masked references are refused there. Errors keep their taxonomy code (`DAG_ML_<CODE>`, status `error`) and carry the outer fold and candidate in `provider_error_detail`.
- Re-verification. Preflight checks everything the provider returns before publishing it, without a new CV:
  - partitions, unsplit components and unique fold IDs;
  - inner folds inside each outer training pool;
  - the exact grid, and the selection as the minimum inner RMSE with the tie rule;
  - the exact fit count;
  - one OOF row per sample with its exact target bits;
  - finite, in-range provider scores.

  Fold-train means then come from Methods `summary`. Model and baseline RMSE, MAE and R² come from `n4m_stats_regression_scores` on the OOF rows. The provider's MSE, RMSE and MAE must agree within a relative 1e-9 (`PROVIDER_SCORES_DISAGREE_WITH_METHODS` otherwise). R² and skill are ratios that can exceed the double range inside the domain. They are then published as `{significand, exponent, representation}` (value = significand · 2^exponent), never as an infinity and never as absent. Only a constant target gives an undefined R².
- Metrics:
  - `probe.plan`, including `numerical_rank`;
  - `probe.folds`: FIT/EVAL sample IDs, inner RMSE per component count, selection and train mean;
  - `probe.oof_predictions`, `probe.rmse`, `probe.mae`;
  - `probe.r2_oof` (`1 − SSE/Σ(y − ȳ_eval)²`), `undefined` for constant evaluation targets;
  - `probe.skill_vs_train_mean` (`1 − SSE_model/SSE_fold_train_mean` on the same rows), `undefined` when the baseline error is zero;
  - `probe.train_mean_rmse`, `probe.train_mean_mae`, and `probe.domain_scores` (per structured domain).

  There is no interval, because folds are not independent observations. Every metric publishes `numerical_domain`.
- Numerical domain (rules 13 and 15). The kernels accept finite values and every nonzero |x| in [2^-256, 2^256]. Targets and predictions, which are scored through differences, also need a spread of at most 2^32 per array; the aggregation of spectra is a summary and has only the magnitude bounds. Means and scores carry errors of order n·ε. Outside it, Methods refuses before computing, and the probe is `unsupported` with `NUMERICAL_DOMAIN_EXCEEDED`. Inside it, the Methods NIPALS PLS estimator refuses strongly scaled data (about X·2^±30 and beyond) with an explicit `NumericalFailure`, because its thresholds are absolute `DBL_EPSILON`. The probe then reports an `error` with context; this is a known upstream limit, never a wrong value.
- Finding. Skill ≤ 0 emits `probe.no_skill_over_train_mean.v1` (info, confidence `unknown`). A weak probe does not show that every calibration is impossible.

The DAG seed is the shared `derive_seed` over the source, target and estimator. The current grouped folds are deterministic and do not consume it.

The independent golden (`crates/nirs4all-preflight/tests/fixtures/generate_probe_sklearn_v1.py`: scikit-learn 1.7.2, NumPy 2.2.6) has three cases: base, rank-deficient and technical repeats. On every case and both estimators, outer and inner folds, selected components and the numerical rank are identical. OOF predictions, fold-train means, RMSE, MAE, R², skill, baseline RMSE and, per domain, RMSE and baseline RMSE agree within a strictly relative 1e-7, on CPU and in WASM; both also check the domain keys and counts. The golden has no per-domain MAE or skill and no baseline MAE, so those outputs are not compared with it.

Tampered provider results are all rejected without a new CV: non-minimal selections, ties resolved to more components, duplicate fold IDs, a wrong fit count, a negative RMSE, an infinite MAE, and scores or OOF rows altered by 0.1 %. On a batch-confounded fixture, sample-level folds give skill above 0.9. Holding out batches as groups never splits a batch and gives skill below 0.2. Under CI, a missing `N4M_LIBRARY_PATH` fails these tests instead of skipping them.
