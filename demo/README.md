# nirs4all-preflight demo

Static Vite/React application published at https://gbeurier.github.io/nirs4all-preflight/. Dropping files or a whole folder anywhere on the landing page (or choosing them with the file or folder picker) starts the analysis directly: there is no configuration step. The drop zone is the shared `nirs4all-ui` `DatasetDropzone`; while files are read, IO and Formats load and IO assembles the dataset, the zone shows each step. The files go through the published `@nirs4all/formats-wasm` and `@nirs4all/io-wasm` (0.2.13, which joins X/Y/metadata tables by their shared sample identifier) packages, which decode, infer roles, headers, partitions, joins and the task type, and assemble the dataset; when the spectra carry no identifier, a target or metadata table's identifier is used only if IO finds it unique per row; the real Rust and Methods WASM engines then run in a worker. Accepted inputs are one table with a header row, separate files following the nirs4all naming convention (`X_train` / `y_train` / `metadata_train`, `Xcal` / `Ycal` / `Mcal`, and their test or `val` counterparts), spectroscopy files supported by Formats, or a canonical preflight JSON input. The workspace header lists how IO read each file. Empty files are skipped and reported.

`src/dataset-io.ts` chains IO's inference and native assembly (`importFiles`). `src/dataset.ts` adapts the assembled v2 contract to preflight, keeping every spectral source, target, partition, declared identity, repetition and per-sample metadata column (strings categorical, numbers continuous; columns that vary between repeats of one sample are acquisition-level and left out). IO's binary or multiclass task inference declares the target categorical. IO does all parsing and joining. Missing cells remain missing, repetitions stay separate, no random split is introduced, and unknown independence/repetition types remain unknown.

The landing page offers four examples in one row: **Beer** (60 × 576, regression) and **Anopheles** (333 × 2,151, binary classification), using the same real CSV extracts as Web, and two synthetic sets (clean, with pitfalls). The original train/test splits stay intact. With the 0.1.2 engine the full-resolution Anopheles analysis takes about 6 s and a 424 × 2,151 set with eight metadata columns about 15 s (Node 24 measurements); analysis remains cancellable. The **Full computation (slow)** setting declares `options.clustering.subsample_refit`, `options.domain_shift.energy_on_spectra` and `options.domain_shift.monitor_on_spectra`, which restore the heavier PCA refits and complete-spectra computations (several minutes on such sets). [Demo provenance and licenses](public/data/demo/SOURCES.md) document sources and inherited transformations; `SHA256SUMS` records the copied bytes.

Imports are saved per dataset in IndexedDB through `idb-keyval` and listed as recent datasets. They can be reopened after reload or removed. Storage failure offers analysis without saving. This library belongs to this app's browser origin and device; it is not a cross-site library shared with Web or QualiNIRS.

The published IO/Formats npm packages currently contain Node-target wasm-bindgen glue. `scripts/browser-wasm.ts` is a narrow Vite adapter: it keeps that generated glue and the package binaries, replaces only the filesystem bootstrap with lazy browser loading, and works in development and production without sibling checkouts or a Rust toolchain.

`src/engine.ts` owns worker messages and cancellation; `src/runtime.ts` loads the distributed `@nirs4all/preflight` package. The page follows the nirs4all.org style: a landing page (file drop, examples and recent datasets), then a four-step journey while the engine analyses in the background — **Your data** (raw input only: spectra explorer with hover/selection and missing-cell marks, sample composition, declared references, sortable sample table linked to the explorer), **Diagnosis** (plain-language control points read from engine counts, engine findings, populations, near duplicates and reference conflicts, PCA structure, SNV and balanced-repeat sensitivity, exploratory clustering, repeatability with engine confidence intervals and noise proxy, target, metadata associations, confounding, domain shift and the grouped validation probe — each 0.1.0 section appears only when the report carries its metrics), **Evidence** (filterable metric table grouped by family, readable structured values, CSV export, capabilities, limitations, provenance) and **Export** (JSON, HTML, evidence CSV, input). Links from control points and findings open the step that holds their chart or evidence. `nirs4all-ui/qualification` supplies the presentation components and charts (`SpectraExplorer`, `CheckList`, `PopulationFlow`, `RepeatabilityProfile`, `EigenvalueScree`, `ScoreMap`, `TargetDistribution`, `CapabilityGrid`, `StatTile`, `MeasureBars`, `HypothesisTestTable`, `ComparisonMatrix`, `ReplicateHistogram`) and the pure selectors that read them from the engine report; `src/views.ts` only joins report rows to declared input metadata and counts declared rows; `src/Blocks.tsx` lays out the 0.1.0 capability sections; `src/checks.ts` turns engine counts and published decisions into control points (zero → OK, never a calibrated threshold or a global score). Source/target selectors scope the displayed charts; the engine always receives all sources and targets. Each report retains the exact input, populations, context, availability and synthetic origin.

`@nirs4all/preflight` is pinned to its published 0.1.3 package; `src/engine.integration.test.tsx` runs that installed Rust/WASM, Methods and dag-ml engine and checks the rendered diagnostics. Fixture tests cover additional layout cases. `nirs4all-ui` is pinned to an exact commit of its GitHub repository until the next npm release ships the qualification charts; replace the commit with that version then. Run `npm ci`, `npm test`, `npm run build` and `npm run preview`. With preview running, `CHROME=/path/to/chrome npm run test:browser` exercises real IO/Formats loading without configuration, preflight WASM analysis, persistence across reload, removal, and mobile layout. Alternatively install Chromium with `npx playwright-core install chromium`. Unit tests also exercise the published IO/Formats binaries on combined/separate tables, reordered ID joins, train/test/predict partitions, missing cells, repeated samples, categorical targets, JCAMP spectra and the nirs4all-io sample files, plus IndexedDB persistence. `src/nirs4all-data.test.ts` imports real folders from a sibling `nirs4all-data` checkout when present (skipped otherwise). `.github/workflows/pages.yml` builds and publishes the project site.

The profile is exploratory alpha. Advanced protocols and language/platform qualification limits are listed in the engine report. Browser checks cover headless Chromium, including the real WASM analysis, PCA and text table, downloads, cancellation, stale responses and narrow layouts; screen-reader and other-browser qualification remain open.
