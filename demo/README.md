# nirs4all-preflight demo

Static Vite/React application published at https://gbeurier.github.io/nirs4all-preflight/. It imports dataset files locally through the published `@nirs4all/io-wasm` and `@nirs4all/formats-wasm` packages, then runs the real Rust and Methods WASM engines in a worker. CSV/TSV tables, separate X/Y/metadata files, and spectroscopy files supported by Formats can be selected together. Companion files must be included in the same selection. Canonical preflight JSON remains available under the advanced import disclosure.

`nirs4all-ui/datasetBuilder` supplies the source, role, column mapping, configuration and validation UI; `DatasetPreviewCard` supplies the local library cards. `src/dataset-io.ts` connects those display contracts to IO's inference and native assembly. `src/dataset.ts` adapts the assembled v2 contract to preflight, keeping every spectral source, target, partition, declared identity and repetition. IO does all parsing and joining. Missing cells remain missing, repetitions stay separate, no random split is introduced, and unknown independence/repetition types remain unknown. Unsupported vertical headers or non-spectral modalities are refused. The generic builder's estimated split and transformation controls are hidden for this diagnostic workflow.

The landing page also offers **Beer** (60 × 576, regression) and **Anopheles** (333 × 2,151, binary classification), using the same real CSV extracts as Web. A click loads only the selected dataset, assembles it through native IO and analyses it with preflight. The original train/test splits stay intact; binary 0/1 labels are declared categorical. Full-resolution Anopheles analysis can take several minutes with the 0.1.0 engine; the page states this and analysis remains cancellable. Shared `DatasetPreviewCard` components display counts, task, attribution and license links. [Demo provenance and licenses](public/data/demo/SOURCES.md) document sources and inherited transformations; `SHA256SUMS` records the copied bytes.

Imports are saved per dataset in IndexedDB through `idb-keyval`. They can be reopened after reload or removed from the landing page. Storage failure offers analysis without saving. This library belongs to this app's browser origin and device; it is not a cross-site library shared with Web or QualiNIRS.

The published IO/Formats npm packages currently contain Node-target wasm-bindgen glue. `scripts/browser-wasm.ts` is a narrow Vite adapter: it keeps that generated glue and the package binaries, replaces only the filesystem bootstrap with lazy browser loading, and works in development and production without sibling checkouts or a Rust toolchain.

`src/engine.ts` owns worker messages and cancellation; `src/runtime.ts` loads the distributed `@nirs4all/preflight` package. The page follows the nirs4all.org style: a landing page (dataset import and configuration, saved datasets, canonical JSON or synthetic sets), then a four-step journey while the engine analyses in the background — **Your data** (raw input only: spectra explorer with hover/selection and missing-cell marks, sample composition, declared references, sortable sample table linked to the explorer), **Diagnosis** (plain-language control points read from engine counts, engine findings, populations, near duplicates and reference conflicts, PCA structure, SNV and balanced-repeat sensitivity, exploratory clustering, repeatability with engine confidence intervals and noise proxy, target, metadata associations, confounding, domain shift and the grouped validation probe — each 0.1.0 section appears only when the report carries its metrics), **Evidence** (filterable metric table, capabilities, limitations, provenance) and **Export**. Links from control points and findings open the step that holds their chart or evidence. `nirs4all-ui/qualification` supplies the presentation components and charts (`SpectraExplorer`, `CheckList`, `PopulationFlow`, `RepeatabilityProfile`, `EigenvalueScree`, `ScoreMap`, `TargetDistribution`, `CapabilityGrid`, `StatTile`, `MeasureBars`, `HypothesisTestTable`, `ComparisonMatrix`, `ReplicateHistogram`) and the pure selectors that read them from the engine report; `src/views.ts` only joins report rows to declared input metadata and counts declared rows; `src/Blocks.tsx` lays out the 0.1.0 capability sections; `src/checks.ts` turns engine counts and published decisions into control points (zero → OK, never a calibrated threshold or a global score). Source/target selectors scope the displayed charts; the engine always receives all sources and targets. Each report retains the exact input, populations, context, availability and synthetic origin.

`@nirs4all/preflight` is pinned to its published 0.1.0 package; `src/engine.integration.test.tsx` runs that installed Rust/WASM, Methods and dag-ml engine and checks the rendered diagnostics. Fixture tests cover additional layout cases. `nirs4all-ui` is pinned to an exact commit of its GitHub repository until the next npm release ships the qualification charts; replace the commit with that version then. Run `npm ci`, `npm test`, `npm run build` and `npm run preview`. With preview running, `CHROME=/path/to/chrome npm run test:browser` exercises real IO/Formats loading, the shared builder, preflight WASM analysis, persistence across reload, removal, and mobile layout. Alternatively install Chromium with `npx playwright-core install chromium`. Unit tests also exercise the published IO/Formats binaries on combined/separate tables, reordered ID joins, train/test/predict partitions, missing cells, repeated samples, categorical targets and JCAMP spectra, plus IndexedDB persistence. `.github/workflows/pages.yml` builds and publishes the project site.

The profile is exploratory alpha. Advanced protocols and language/platform qualification limits are listed in the engine report. Browser checks cover headless Chromium, including the real WASM analysis, PCA and text table, downloads, cancellation, stale responses and narrow layouts; screen-reader and other-browser qualification remain open.
