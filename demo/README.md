# nirs4all-preflight demo

Static Vite/React application published at https://gbeurier.github.io/nirs4all-preflight/. Dropping files or a whole folder anywhere on the landing page (or choosing them with the file or folder picker) starts the analysis directly: there is no configuration step. The drop zone is the shared `nirs4all-ui` `DatasetDropzone`; while files are read, IO and Formats load and IO assembles the dataset, the zone shows each step. The files go through the published `@nirs4all/formats-wasm` and `@nirs4all/io-wasm` (0.2.14, which joins X/Y/metadata tables by their shared sample identifier) packages, which decode, infer roles, headers, partitions, joins and the task type, and assemble the dataset; when the spectra carry no identifier, a target or metadata table's identifier is used only if IO finds it unique per row; the real Rust and Methods WASM engines then run in a worker. Accepted inputs are one table with a header row, separate files following the nirs4all naming convention (`X_train` / `y_train` / `metadata_train`, `Xcal` / `Ycal` / `Mcal`, and their test or `val` counterparts), spectroscopy files supported by Formats, or a canonical preflight JSON input. The workspace header lists how IO read each file. Empty files are skipped and reported.

`src/dataset-io.ts` chains IO's inference and native assembly (`importFiles`). `src/dataset.ts` adapts the assembled v2 contract to preflight, keeping every spectral source, target, partition, declared identity, repetition and per-sample metadata column (strings categorical, numbers continuous; columns that vary between repeats of one sample are acquisition-level and left out). IO's binary or multiclass task inference declares the target categorical. IO does all parsing and joining. Missing cells remain missing, repetitions stay separate, no random split is introduced, and unknown independence/repetition types remain unknown.

The landing page offers four examples in one row: **Beer** (60 × 576, regression) and **Anopheles** (333 × 2,151, binary classification), using the same real CSV extracts as Web, and two synthetic sets (clean, with pitfalls). The original train/test splits stay intact. Settings provide an expandable analysis menu for spectral quality, structure sensitivity, repeatability, exploratory groups, metadata associations, confounding, domain comparisons and validation probes. Integrity, population counts, canonical PCA and target descriptions always run. Expensive PCA refits and full-spectrum domain computations are independent options. Recorded Chromium timings on all four examples appear per family; each run includes the shared checks and reports computed/unavailable counts. These are device-specific examples, including refusals when a protocol's prerequisites are absent, not performance guarantees. [Demo provenance and licenses](public/data/demo/SOURCES.md) document sources and inherited transformations; `SHA256SUMS` records the copied bytes.

Imports are saved per dataset in IndexedDB through `idb-keyval` and listed as recent datasets. They can be reopened after reload or removed. Storage failure offers analysis without saving. This library belongs to this app's browser origin and device; it is not a cross-site library shared with Web or QualiNIRS.

The published IO/Formats npm packages currently contain Node-target wasm-bindgen glue. `scripts/browser-wasm.ts` is a narrow Vite adapter: it keeps that generated glue and the package binaries, replaces only the filesystem bootstrap with lazy browser loading, and keeps parsing in the published IO/Formats packages. Building preflight itself requires the Rust/WASM toolchain described below.

`src/engine.ts` owns worker messages and cancellation; `src/runtime.ts` loads this checkout’s `bindings/wasm` package through a local npm dependency so the UI and engine contracts stay aligned. The page follows the nirs4all.org style: a landing page (file drop, examples and recent datasets), then a four-step journey while the engine analyses in the background — **Your data** (raw input only: spectra explorer with hover/selection and missing-cell marks, sample composition, declared references, sortable sample table linked to the explorer), **Diagnosis** (plain-language control points read from engine counts, engine findings, populations, near duplicates and reference conflicts, PCA structure, SNV and balanced-repeat sensitivity, exploratory clustering, repeatability with engine confidence intervals and noise proxy, target, metadata associations, confounding, domain shift and the grouped validation probe — each 0.1.0 section appears only when the report carries its metrics), **Evidence** (filterable metric table grouped by family, readable structured values, CSV export, capabilities, limitations, provenance) and **Export** (JSON, HTML, evidence CSV, input). Links from control points and findings open the step that holds their chart or evidence. `nirs4all-ui/qualification` supplies the presentation components and charts (`SpectraExplorer`, `CheckList`, `PopulationFlow`, `RepeatabilityProfile`, `EigenvalueScree`, `ScoreMap`, `TargetDistribution`, `CapabilityGrid`, `StatTile`, `MeasureBars`, `HypothesisTestTable`, `ComparisonMatrix`, `ReplicateHistogram`) and the pure selectors that read them from the engine report; `src/views.ts` only joins report rows to declared input metadata and counts declared rows; `src/Blocks.tsx` lays out the 0.1.0 capability sections; `src/checks.ts` turns engine counts and published decisions into control points (zero → OK, never a calibrated threshold or a global score). Source/target selectors scope the displayed charts; the engine always receives all sources and targets. Each report retains the exact input, populations, context, availability and synthetic origin.

Build the local runtime before starting the demo, from the repository root:

```sh
npm ci --prefix bindings/wasm
npm run build:native --prefix bindings/wasm
npm ci --prefix demo
npm test --prefix demo
npm run build --prefix demo
npm run preview --prefix demo
```

`wasm-pack` and the `wasm32-unknown-unknown` Rust target are required. The Pages workflow performs the same build. `nirs4all-ui` is pinned to the unpublished local build `0.2.2-local.20261107.2` (`vendor/nirs4all-ui-0.2.2-local.20261107.2.tgz` with its provenance file; `vendor/` is git-ignored, so a clean checkout or CI needs that tarball staged first). It already contains the shared qualification changes that `patch-package` used to apply to npm 0.2.0, so no install-time patch remains. Numerical kernels remain in Methods, and charts remain in UI. `src/engine.integration.test.tsx` runs the local Rust/WASM engine with published Methods and DAG-ML binaries. With preview running, `CHROME=/path/to/chrome npm run test:browser` exercises imports, persisted reuse, repeat declarations and real examples; `node demo/scripts/review-smoke.mjs` from the repository root verifies settings, filtering, selective exports and chart downloads. Alternatively install Chromium with `npx playwright-core install chromium`.

Unit tests also exercise the published IO/Formats binaries on combined/separate tables, reordered ID joins, train/test/predict partitions, missing cells, repeated samples, categorical targets, JCAMP spectra and the nirs4all-io sample files, plus IndexedDB persistence. `src/nirs4all-data.test.ts` imports real folders from a sibling `nirs4all-data` checkout when present (skipped otherwise). `.github/workflows/pages.yml` builds and publishes the project site.

The profile is exploratory alpha. Advanced protocols and language/platform qualification limits are listed in the engine report. Browser checks cover headless Chromium, including the real WASM analysis, PCA and text table, downloads, cancellation, stale responses and narrow layouts; screen-reader and other-browser qualification remain open.

Metadata roles apply to every metadata-dependent protocol. A column can be an analysis group/covariate, an identifier or excluded. Names such as `id_scan` are proposed as identifiers; every choice is editable. Original columns and physical/repetition identities remain intact. Varying selected metadata is available for explorer/PCA colours; continuous values use a gradient, categories use discrete colours. PCA units receive a target colour only if their calibration member references agree. Retained-test target values are never used.

The synthetic pitfalls example declares technical repeats, two instruments, campaigns and generic batch metadata. Real-example sources and licenses are linked on both the landing page and loaded dataset header; no fabricated acquisition metadata is added to Beer or Anopheles.

Near-duplicate tolerance can be declared manually or estimated from complete calibration technical repeats: Methods computes the RMS distance for each within-physical-sample pair in the same instrument/campaign/repetition-type context, then its quartiles. The source-level convention is Q3 + 1.5 × IQR, requiring at least three repeat groups and at most 10,000 pairs. It uses neither target values nor retained-test spectra. This is an exploratory convention, not a calibrated duplicate boundary; all pairs receive equal weight, so samples with more repeats contribute more distances. The report records its method and group/pair counts. Continuous-reference contradiction tolerances remain domain declarations; categorical comparisons use different classes. Baseline sensitivity compares raw geometry with Methods linear detrending of acquisitions before aggregation, alongside SNV and repeat balancing. Its PCA uses Methods’ resolution in the transformed view; there is no separately qualified end-to-end detrending error bound.

Evidence filters and checkboxes control the CSV/JSON/HTML indicator selection across navigation. Partial exports are labelled partial and omit findings requiring any omitted evidence context. Raw-input export remains complete. Each chart offers SVG and chart-table CSV downloads; section tables can be exported together. SVGs retain resolved theme styles and legend notes; shared table cells retain raw numeric values for CSV despite rounded on-screen formatting. The spectral table browses one selected band; the canonical input export retains every spectral value. English UI vocabulary uses Calibration versus Retained test; wire identifiers such as `development` are preserved. The shared English vocabulary is exported as `NIRS_TERMS` from `nirs4all-ui/qualification` for other hosts.

To reproduce the timing artifact, build the optional benchmark entry, start preview, then run the profiler in another terminal:

```sh
PREFLIGHT_PROFILE=1 npm run build --prefix demo
npm run preview --prefix demo
CHROME=/path/to/chrome node demo/scripts/profile-analysis.mjs
```

The profiler writes `src/data/analysis-timings.json` with browser, CPU, date, configuration method, timing and indicator availability. Rebuild normally afterward to include the new measurements and omit the benchmark entry from the product build. Loading/IO and rendering are excluded; the workspace's total elapsed time includes worker communication and initial runtime loading. Heavy optional variants are not benchmarked.
