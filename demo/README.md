# nirs4all-preflight demo

Static Vite/React application published at https://gbeurier.github.io/nirs4all-preflight/. It accepts canonical JSON already assembled by the host and runs the real Rust and Methods WASM engines in a worker. No scientific calculation or vendor parser lives in the page.

`src/engine.ts` owns worker messages and cancellation; `src/runtime.ts` loads the distributed `@nirs4all/preflight` package. The page follows the nirs4all.org style: a landing page (drag-and-drop JSON or synthetic sets), then a four-step journey while the engine analyses in the background — **Your data** (raw input only: spectra explorer with hover/selection and missing-cell marks, sample composition, declared references, sortable sample table linked to the explorer), **Diagnosis** (plain-language control points read from engine counts, engine findings, populations, near duplicates and reference conflicts, PCA structure, SNV and balanced-repeat sensitivity, exploratory clustering, repeatability with engine confidence intervals and noise proxy, target, metadata associations, confounding, domain shift and the grouped validation probe — each 0.1.0 section appears only when the report carries its metrics), **Evidence** (filterable metric table, capabilities, limitations, provenance) and **Export**. Links from control points and findings open the step that holds their chart or evidence. `nirs4all-ui/qualification` supplies the presentation components and charts (`SpectraExplorer`, `CheckList`, `PopulationFlow`, `RepeatabilityProfile`, `EigenvalueScree`, `ScoreMap`, `TargetDistribution`, `CapabilityGrid`, `StatTile`, `MeasureBars`, `HypothesisTestTable`, `ComparisonMatrix`, `ReplicateHistogram`) and the pure selectors that read them from the engine report; `src/views.ts` only joins report rows to declared input metadata and counts declared rows; `src/Blocks.tsx` lays out the 0.1.0 capability sections; `src/checks.ts` turns engine counts and published decisions into control points (zero → OK, never a calibrated threshold or a global score). Source/target selectors scope the displayed charts; the engine always receives all sources and targets. Each report retains the exact input, populations, context, availability and synthetic origin.

`@nirs4all/preflight` is pinned to its published package. `nirs4all-ui` is pinned to an exact commit of its GitHub repository until the next npm release ships the qualification charts; replace the commit with that version then. Run `npm ci`, `npm test`, `npm run build` and `npm run preview` (the Vite dev server does not serve the packaged WASM; use the preview). `.github/workflows/pages.yml` builds and publishes the project site.

The profile is exploratory alpha. Advanced protocols and language/platform qualification limits are listed in the engine report. Browser checks cover headless Chromium, including the real WASM analysis, PCA and text table, downloads, cancellation, stale responses and narrow layouts; screen-reader and other-browser qualification remain open.
